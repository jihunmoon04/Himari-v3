상태: **Proposed**. 소유자 결정 Q1~Q4 모두 권고대로 정함(2026-10-31, §10).

> 소유자(2026-10-31): 애니메이션은 세 갈래로 생각 중이다.
> 1. 에이전트가 직접 조작하는 애니메이션: 휠체어 이동, 감정 표정 추가 등

## 1. 범위

이 패킷에서 만드는 것
- **자산 형식**: Aseprite 원본 → 내보내기 스크립트 → 앱이 읽는 시트 PNG 한 장과 `character.json`(§3)
- **앱 쪽 재생기**: 시트를 읽어 몸 동작, 얼굴(표정·눈·입)을 한 장으로 합쳐 그리는 `CharacterRenderer`와, 지금 무엇을 보여 줄지 정하는 `CharacterAnimator`(§4, §5)
- **우선순위 규칙**: 여러 요청이 겹칠 때의 규칙(§5.2)
- **첫 적용**: 지금 있는 깜빡임·말하기·표정 8종을 새 구조로 옮기고, 대기 모션(호흡, 헤일로)을 켠다(§8).

만들지 않는 것
- 새 그림(졸기, 바퀴 회전, 소품). 구조만 받쳐 둔다(§9).
- 사용자 동작 감지(갈래 2). 요청을 넣을 자리만 둔다(§5.2의 `Reaction`).
- 서버 변경.

## 3. 자산

### 3.1 원본과 내보내기

- **원본**: `animation-preview/pixel/clean/`의 Aseprite 파일이다. 사람과 에이전트가 고치는 것은 이것뿐이다.
  - `body.aseprite`: 몸 동작. 태그 하나가 동작 하나다(`idle`, `sleep`, 나중에 `roll` 등). `idle-test.aseprite`(파츠를 합친 idle 6프레임)에서 만들었고, `sleep`은 `tools/sleep.lua`가 같은 파츠를 움직여 뒤에 붙였다(§5.4). 얼굴 영역은 neutral 얼굴을 담는다.
  - `faces.aseprite`: 얼굴. 표정마다 프레임 하나(태그 이름 = 표정 이름)와, 그 표정의 눈·입 변형(§3.3)이 들어간다. 변형은 `eyes/half`처럼 이름 붙인 레이어에 기본 얼굴과 다른 픽셀만 담는다.
  - 두 파일은 `tools/sources.lua`가 PR #141의 그림에서 한 번 만들었다. 이제부터는 이 둘이 원본이다.
- **내보내기**: `tools/export.lua`가 두 원본을 읽어 `Himari.Companion/Assets/character.png`(색 인덱스 시트 한 장)와 `character.json`을 쓴다.
  - 같은 그림은 시트에 한 번만 넣는다. 예를 들어 깜빡임 반 프레임은 두 번 쓰이지만 시트에는 한 장이다.
  - 사람이 쓴 이름은 한 번만 적는다.
- **검사**: 내보내기 스크립트는 다음을 어기면 실패한다.
  - 모든 그림이 `himari-32.gpl`의 색만 쓴다.
  - 그림이 색 인덱스 모드다.
  - 반복 동작 태그의 사용자 데이터 `loopFrom=N`이 프레임 범위 안이다(아래 §3.4). 태그끼리 프레임이 겹치지 않는다.
  - 모든 동작의 첫 프레임은 쉬는 자세(idle 첫 프레임)와 같다. 한 번만 도는 동작은 마지막 프레임도 같다(§5.3). 반복 동작은 자기 첫 프레임으로 돌아가므로 마지막 프레임은 보지 않는다.
  - 얼굴 표시(§3.2)가 모든 몸 프레임에 있다.
  - 표정 이름이 서버 목록 8개를 모두 덮는다.
- **결과물은 저장소에 넣는다**(Q3). CI와 빌드에는 Aseprite가 없다. 대신 UI 테스트가 결과물과 원본이 어긋나지 않았는지 픽셀로 확인한다(§7).

### 3.2 몸 동작과 얼굴 위치

- 몸 동작의 프레임은 파츠를 이미 합친 그림이다. 숨쉬기로 상체가 1px 오르거나 헤일로가 2px 뜨는 것은 그림에 들어 있다.
- 얼굴은 상체와 함께 움직여야 한다. 그래서 몸 프레임마다 얼굴을 놓을 자리를 숨긴 레이어 **`@face`**의 1×1 점으로 적는다. 숨쉬기 프레임에서는 점도 1px 올라간다.
  - 처음에는 슬라이스(프레임별 키)로 하려 했으나, Aseprite Lua API로는 프레임별 슬라이스 키를 쓸 수 없어 점 레이어로 바꿨다.
  - `export.lua`가 점 위치와 기준 위치의 차이를 각 프레임의 `face`로 옮긴다.
- 몸 프레임은 neutral 얼굴을 담고 있다. 얼굴 그림이 그 위를 덮으므로, 표정을 바꿔도 몸 그림을 다시 만들 필요가 없다.

### 3.3 얼굴

- **얼굴 영역**: (101, 47)부터 33×26이다. 턱의 손(129 이상, 66 이상)은 몸 쪽이므로 투명하게 둔다.
  - 표정 얼굴은 이 영역을 통째로 덮는다(PR #141의 `mood.lua` 결과에서 잘라 낸다).
- **눈 변형**: `half`, `closed`
- **입 변형**: `small`, `wide`
  - 눈·입 변형은 그 표정 얼굴 위에 겹치는 작은 그림이다. 좌표는 얼굴 영역 기준이다.
- **표정마다 가진 변형만 쓴다.** 없는 변형을 요청하면 그 표정의 기본 얼굴을 그대로 둔다.
  - 예: happy는 이미 윙크라서 `closed`가 없어도 된다.
  - 표정 8종 모두 입 변형을 가진다. 눈 변형은 happy를 뺀 7종이 가진다(happy는 이미 눈을 감고 웃는 얼굴이라 깜빡이지 않는다). neutral은 손으로, 나머지는 `tools/mood-variants.lua`가 그 표정의 속눈썹 선에서 만들었다.

### 3.4 `character.json`

```json
{
  "version": 1,
  "canvas": [205, 206],
  "sheet": "character.png",
  "face": { "origin": [101, 47], "size": [33, 26] },
  "clips": {
    "idle": { "loop": true, "frames": [
      { "src": [0, 0, 205, 206], "ms": 1250, "face": [0, 0] },
      { "src": [205, 0, 205, 206], "ms": 250, "face": [0, -1] } ] }
  },
  "faces": {
    "neutral": { "src": [410, 206, 33, 26],
                 "eyes": { "closed": { "src": [443, 206, 25, 11], "at": [3, 7] }, "half": { "src": [468, 206, 25, 9], "at": [3, 7] } },
                 "mouth": { "small": { "src": [493, 206, 3, 2], "at": [12, 18] }, "wide": { "src": [496, 206, 5, 3], "at": [11, 18] } } },
    "happy": { "src": [501, 206, 33, 26],
               "mouth": { "small": { "src": [534, 206, 2, 1], "at": [12, 19] }, "wide": { "src": [536, 206, 3, 3], "at": [12, 19] } } }
  }
}
```

- 좌표는 모두 도트 단위, `src`는 시트 안의 사각형이다. 위 값은 실제 `Assets/character.json`에서 줄인 것이다(시트 1007×1056, 그림 54조각).
- 몸 프레임에 `"eyes"`를 적으면 그 프레임의 눈을 강제한다(§5.2). 원본에서는 `body.aseprite`의 숨긴 레이어 **`@eyes`**에 그 프레임의 셀을 두고 셀 사용자 데이터에 `half`나 `closed`를 적는다. `"mouth"`도 앱은 읽지만 아직 쓰는 프레임이 없다.
- 반복 동작에 `"loopFrom": n`(0부터 센 프레임 번호)이 있으면 앞의 n프레임은 한 번만 돌고, 그 뒤부터 반복한다(`sleep`의 잠드는 부분). 원본에서는 태그 사용자 데이터 `loopFrom=N`(1부터)으로 적는다. 단발 동작에는 쓸 수 없다.
- 앱은 `version`이 다르면 시작할 때 실패한다. 자산과 코드가 같은 커밋에서 오므로 실제로 어긋날 일은 없고, 테스트로 지킨다.

## 4. 그리기: `CharacterRenderer`

- `Character`는 계속 WPF `Image`다. `CharacterRenderer`가 만든 205×206 `WriteableBitmap` 한 장이 `Source`로 들어간다.
  - 크기, 반전, 위치 계산, 마우스, `Opacity`, 창 비율(`Source.Width/Height`)을 쓰는 곳(§2)은 하나도 바뀌지 않는다.
  - 처음 설계는 `FrameworkElement`(`CharacterView`)가 조각을 따로 확대해 그리는 것이었다. 정수배가 아닌 크기(Q1)에서는 조각마다 반올림이 달라 몸과 얼굴 사이에 1화면픽셀 틈이 생길 수 있어, 1배로 먼저 합치는 쪽으로 바꿨다.
- `Render(pose)`가 1배 버퍼에 다음 순서로 그린다.
  1. 몸 프레임(덮어쓰기)
  2. 표정 얼굴(얼굴 기준 위치 + 프레임의 `face`)
  3. 눈 변형
  4. 입 변형
  - 2–4는 투명한 픽셀을 건너뛴다.
- 시트는 시작할 때 Bgra32 배열로 한 번 풀어 둔다.
- 확대는 지금처럼 `RenderOptions.BitmapScalingMode="NearestNeighbor"`로 한다.
- 다시 그리는 것은 보여 줄 장면(§5.1)이 바뀔 때뿐이다. 같은 장면이면 `Render`는 아무것도 하지 않는다.
- 테두리(hit test)는 지금처럼 사각형 전체다.

## 5. 고르기: `CharacterAnimator`

WPF를 모르는 순수 C# 클래스다. 시각과 입력을 받아 **장면** 하나를 돌려준다. 그래서 계약 테스트에서 그대로 시험할 수 있다(§7).

### 5.1 장면

```csharp
record CharacterPose(string Clip, int Frame, string Mood, string? Eyes, string? Mouth);
CharacterPose Pose(TimeSpan now);
TimeSpan NextChange(TimeSpan now);   // 다음에 장면이 바뀌는 시각
```

- 타이머는 30ms 고정 대신 `NextChange`까지 한 번 기다린다. 가만히 있을 때는 몇백 ms에 한 번만 깨어난다.
- 시각은 `Stopwatch`로 잰다. 테스트는 시각을 직접 넣는다.

### 5.2 세 채널

| 채널 | 정하는 것 | 입력 |
|---|---|---|
| **몸** | 동작 태그와 프레임 | 동작 요청(아래) |
| **표정** | 얼굴 그림 | 서버의 표정(`SetMood`), 설정의 미리보기 |
| **눈·입** | 눈 변형, 입 변형 | 깜빡임 시계, 말하는 중, 몸 프레임의 강제값 |

몸 동작 요청은 세 층 중 하나에 들어간다. 높은 층의 요청이 있으면 그것이 이긴다.

| 층 | 예 | 끝 |
|---|---|---|
| `Directed` (2) | 에이전트가 시킨 이동(바퀴 회전), 앞으로의 에이전트 동작 | 요청한 쪽이 끝냄 |
| `Reaction` (1) | 사용자 동작 반응(갈래 2) | 요청한 쪽이 끝내거나 시간이 다 됨 |
| `Ambient` (0) | `idle`(기본, 항상 있음), 가끔의 대기 동작, 졸기 | `idle`만 끝나지 않음 |

```csharp
AnimationRequest Request(string clip, AnimationLayer layer, TimeSpan? duration = null);
void Release(AnimationRequest request);
```

- 같은 층에서는 나중 요청이 이긴다. 끝난 요청은 버린다.
- 말하기는 몸 동작이 아니다. 입만 바꾼다. 그래서 휠체어로 이동하면서도 말할 수 있다.
- 몸 프레임은 `"eyes": "closed"`처럼 눈·입을 강제할 수 있다(졸기). 강제값은 깜빡임보다 앞선다. 다만 말하는 동안에는 눈을 뜬다(감은 채 말하지 않는다).

### 5.3 바뀔 때

- 동작은 쉬는 자세로 시작하고 쉬는 자세로 끝난다(§3.1 검사).
- 높은 층의 요청은 **바로** 끼어든다. 우리 동작은 쉬는 자세에서 1–2px 차이라 끊겨도 튀어 보이지 않는다.
- 요청이 끝나면 아래 층 동작을 첫 프레임부터 다시 튼다. 반복 동작을 중간에서 이어 가지 않는다.
- 시간을 주지 않은 단발 동작은 **보이기 시작한 때부터** 한 번 끝까지 돈다. 가려졌다가 다시 보이면 처음부터 다시 끝까지 돈다(PR #142 검수). 시간을 준 요청(`duration`)은 요청한 때부터 잰다. `Release`하면 바로 끝난다.

### 5.4 깜빡임과 말하기

- **깜빡임**: 마지막 깜빡임 뒤 2.5–6초 사이 무작위로 `half` 60ms → `closed` 90ms → `half` 60ms를 튼다. 다섯 번에 한 번은 두 번 연달아 깜빡인다(Q2).
  - 무작위 씨앗을 넣을 수 있어 테스트는 같은 결과를 본다.
- **말하기**: 말하는 동안 `small` → `wide` → `small` → (닫힘)을 130ms씩 돈다. 말이 끝나면 지금 칸을 마치고 닫는다.
- **졸림**: 5분 동안 입력이 없으면 `Ambient`에 `sleep`을 요청한다. 입력이 생기면 바로 `Release`해서 `idle`로 돌아간다(깨는 동작은 따로 없다). `sleep` 그림이 없으면 `idle` 위에서 눈만 감는다.
  - **잠들기**(한 번, 1초): 쉬는 자세 + 반쯤 감은 눈 400ms → 고개 1px 아래 + 반쯤 감은 눈 300ms → 고개 2px 아래, 머리카락 끝·헤일로 1px 아래 + 감은 눈 300ms
  - **자는 중**(반복, 6초에 한 숨): 500ms 12칸. 고개는 3초 동안 2px 아래, 3초 동안 1px 아래다. 머리카락 끝은 500ms, 헤일로는 1초 늦게 같은 방향으로 따라간다. 머리 오른쪽에 z 세 개가 2초 간격으로 나타나, 떠오르며 3px → 7px로 커지고 위에서 흐려지며 사라진다. 파스텔 하늘색에 연한 파랑 테두리다(팔레트에 두 색 추가).
  - 파츠를 아래로 내리면 고정된 휠체어·등받이와 만나던 자리에 틈이 생긴다. `sleep.lua`가 프레임마다 바깥과 이어지지 않은 투명 픽셀을 찾아 쉬는 자세의 색으로 맨 아래 `fill` 레이어에 채운다.

## 7. 시험

- **계약 테스트**(WPF 없음): `CharacterAnimator`를 시각을 넣어 돌린다.
  - 층 우선순위, 끝난 요청 뒤의 복귀, 강제 눈
  - 말하기와 깜빡임의 순서·시간, `NextChange`
  - 없는 변형은 무시
- **UI 테스트**:
  - `character.json`의 모든 `src`가 시트 안에 있는지 확인한다.
  - 모든 표정과 몸 프레임이 그려지는지 확인한다.
  - `CharacterRenderer`가 1배로 그린 결과가 내보내기 스크립트가 만든 기준 그림과 **픽셀까지 같은지** 본다. 기준은 몇 개만 고른다: idle 첫 프레임, 숨쉬기 프레임 + happy, neutral + 감은 눈 + 큰 입, 자는 중 첫 프레임 + 감은 눈.
- **내보내기 스크립트 자체 검사**(§3.1): 팔레트, 색 인덱스, 쉬는 자세, 얼굴 표시, 표정 목록.
