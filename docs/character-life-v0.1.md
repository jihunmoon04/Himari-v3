# 히마리의 삶: 정사·일기·일정 v0.1 (캐릭터 로드맵 1·2단계, 2026-11-25)

[캐릭터 로드맵](character-architecture.md)의 1단계(일관성)와 2단계(삶)를 한 번에 만든다. 같은 저장소를 쓰기 때문이다. 소유자 방침(2026-11-25): **로드맵대로 빨리 만들고, 써 보며 문제가 보이면 고친다.** 그래서 이 문서는 짧고, 세부는 코드와 시험이 정한다(H-72).

## 1. 무엇을 만드나

- **삶 항목**(페르소나마다 따로, H-76 D1): `fact`(정사: 확정된 자기 사실), `diary`(하루 일기, 날짜 하나), `plan`(앞으로 할 일, 날짜 하나).
- **이야기 작가:** 하루에 한 번, 그날의 일기와 내일 일정, 새 정사를 쓰는 백그라운드 작업.
- **기억 정리 넓히기:** 대화에서 HIMARI가 자기에 대해 한 말을 정사로 모은다.
- **프롬프트:** 정사·최근 일기·일정을 runtime state에 넣고, 반려 절에 삶을 다루는 문장 하나.
- **Web:** Settings → **Life**에서 지금 페르소나의 삶을 보고 고치고 지운다. 앱에는 보이지 않는다(D4).

## 2. 저장

- 새 표 하나에 셋을 둔다(스키마 v22): 주인, 페르소나 번호(**고른 페르소나가 없으면 0**), 항목 번호(다시 쓰지 않음), 종류(`fact`·`diary`·`plan`), 날짜(`diary`·`plan`만, 사용자 시간대의 날짜), 글(500자, 일기는 1,500자), 쓴 이(`writer`·`conversation`·`user`), 만든·고친 시각, 물러난 시각(`retired_at`, 지우면 물러남), 근거(대화 번호와 HIMARI 답 `seq`, 있으면).
- 한 페르소나의 살아 있는 `fact`는 200개까지. 넘으면 가장 오래된 작가의 것부터 물러난다(사용자가 쓴 것은 남김).
- 같은 날의 `diary`는 하나다(작가가 다시 쓰면 고침).
- 페르소나를 지우면 그 삶은 남겨 둔다(물러나게 하지 않음). Web에서 그 페르소나가 없으면 보이지 않을 뿐이다. 같은 번호는 다시 쓰이지 않으므로 섞이지 않는다.
- 작가 호출 하나하나를 기억 작업처럼 기록한다(원본 요청·응답, 모델, 토큰, 결과).

## 3. 이야기 작가

- **언제:** 사용자 시간대로 **22:00 이후**(`HIMARI_LIFE_WRITE_AT`, 기본 `22:00`), 지금 페르소나의 오늘 일기가 아직 없으면 쓴다. 서버가 그 시각을 놓쳤으면, 다음에 돌 때 **가장 최근에 빠진 하루 하나만** 쓴다(그 이전은 메우지 않음). `bootstrap/schedule`의 주기 판단에서 돈다. 기억 작업처럼 대화의 Run이 아니다.
- **모델:** 기억 작업 모델(`memory_passes` 능력, H-60)을 쓴다. 하루 토큰 상한도 기억 작업과 같은 방식으로 따로 둔다. `HIMARI_LIFE=0`이면 작가와 프롬프트의 삶이 모두 꺼진다.
- **입력:**
  - 페르소나 글(없으면 기본 말투 한 줄)
  - 살아 있는 정사 전부(상한 안)
  - 최근 일기 3개, 남은 일정
  - 그날의 일화(사용자와 무엇을 했는지, 최대 5개, 근거로만)
  - 날짜·요일·계절·시각
- **출력**(JSON): `diary`(그날의 일기 3~6문장, 1인칭, 페르소나의 말투), `plans`(0~3개, 다음 7일 안, 날짜와 한 문장), `facts`(0~3개, 일기가 새로 정한 자기 사실: 친구 이름, 새로 시작한 취미 등).
- **규칙(작가에게 주는 글):**
  - 페르소나가 정한 정체·세계 설정·현실 접점 안에서 쓴다. 페르소나와 정사에 어긋나는 것은 쓰지 않는다(우선순위 정체성 > 정사 > 일기, H-76).
  - 날짜·계절·요일을 부정하지 않는다.
  - **사용자와 함께 한 일을 새로 쓰지 않는다.** 일기가 사용자 이야기를 할 때는 그날 일화에 있는 것만 쓴다.
  - 일정은 히마리 혼자 할 일이다.
- **검사:** 형식·길이·개수, 날짜 범위. 어긋나면 그 호출을 버리고 기록한다(다음 주기에 다시 시도, 하루 3번까지).

## 4. 기억 정리 넓히기

- 기억 작업의 입력에 **지금 페르소나의 정사**(번호와 글)를 더하고, 출력에 `self`를 더한다: `[{"op": "add|update|retire", "id": …, "text": …, "himari_evidence": [seq]}]`.
- HIMARI의 답에서 **HIMARI가 자기 삶에 대해 사실처럼 말한 것**만(취향, 겪은 일, 사람, 계획). 사용자에 대한 것, 농담·가정, 시스템 글에서 온 말은 아니다. 근거는 HIMARI 답 `seq`만 된다.
- 적용하는 페르소나는 **기억 작업을 할 때 고른 페르소나**다. 턴마다 페르소나를 기록하지 않기 때문이다(V3-P108 Q7). 대화 도중 페르소나를 바꾼 경우 조금 섞일 수 있다(알려진 한계).
- 사용자가 쓴 정사(`user`)는 고치거나 물러나게 하지 않는다.

## 5. 프롬프트

- runtime state에 `himari_life`(반려 켬 + 삶 켬일 때):
  - `facts`: 정사(1,500자까지, 사용자가 쓴 것 먼저, 나머지 최신순)
  - `days`: 최근 일기 3개(날짜와 글, 1,500자까지)
  - `plans`: 오늘부터의 일정
- 반려 절에 `LIFE_RULE` 한 문장(요지): runtime_state.himari_life는 사용자와 떨어진 네 삶이다. 페르소나 다음으로 이것과 어긋나지 않게 말한다. 물으면 답하고, 인사나 먼저 말 걸 때 어울리면 꺼내되, 묻지 않았는데 꺼내는 것은 하루 한 번 정도로. 여기에 사용자와 함께 한 일은 없다: 함께 한 일을 지어내지 않는다.
- 자유 wake 문장(`FREE_RULE`)에 한 구절을 더한다: 사용자의 일 대신 네 하루·일정 이야기를 해도 된다(하루 한 번 정도).
- 원칙 문단에서 `himari_life`도 정보로 이름을 댄다(지시가 아님, H-24).

## 6. Web

- Settings → **Life**: 지금 페르소나(없으면 "기본")의 정사·일정·일기(최근 30일)를 보인다. 글 고치기, 지우기(물러남), 정사 더하기(`user`). 리비전으로 동시 수정 충돌을 막는다.
- API: `/api/life`(GET, POST), `/api/life/{id}`(PUT, DELETE). 기기 토큰은 403.

## 7. 하지 않는 것(v0.1)

- 줄거리(몇 주 흐름), 현실 뉴스·날씨는 5단계다.
- 관계 정사와 관계 단계는 3단계다.
- 지난 대화를 다시 읽어 정사를 메우지 않는다(앞으로의 대화만).
- 작가의 일기를 사용자에게 바로 보내지 않는다(대화와 먼저 말 걸기로만 드러남).

## 8. 정한 것

H-76의 D1~D5 그대로다. 이 문서에서 더한 것은 다음과 같다(소유자 방침에 따라 권고안대로 정함, 써 보며 바꿈).

| # | 정한 것 |
| --- | --- |
| L1 | 정사·일기·일정을 runtime state에 넣는다. 로드맵 §6은 정사를 시스템 글 뒤쪽에 둔다고 했지만, 시스템 글은 지시라서 자료인 삶과 맞지 않는다. 기억과 같은 자리로 옮긴다 |
| L2 | 고른 페르소나가 없을 때의 삶은 페르소나 번호 0의 삶이다 |
| L3 | 작가 시각 22:00(사용자 시간대), 빠진 날은 가장 최근 하루만 |
| L4 | 작가 모델 = 기억 작업 모델, 하루 토큰 상한은 따로 |
| L5 | 페르소나를 지워도 그 삶은 남긴다(보이지 않을 뿐) |
