# 대화 화면의 기본기 v0.1

> 2026-10-26 · **PROPOSED (V3-P79)** · 구현 노트 §11. rev. 2: 독립 설계 검수 READY_WITH_CORRECTIONS 반영(§10) — 뒤로/앞으로가 거절·겹칠 때 주소는 보이는 화면의 것으로 바꿈, 쓰는 중인 답의 코드에는 복사 없음, 열 때 대화 목록, 로그아웃 상태의 뒤로 가기, 키보드 감지의 한계. rev. 1: 설계 초안. 소유자 결정 Q1~Q4 권고대로(§8).
>
> 소유자 방향(2026-10-26): Web UX 점검의 항목을 우선순위대로 진행한다. 첫 묶음(V3-P78, 작성 중인 것 지키기)에 이어 두 번째 묶음은 **매일 쓰면서 가장 자주 걸리는 것** 셋이다: 대화마다 주소, iPad 화상 키보드의 Enter, 답과 코드의 복사.
>
> 앞선 결정: 입력창 하나를 홈과 대화가 같이 쓰고 자리마다 초안을 둔다(V3-P78). MCP 앱 화면의 전체 화면은 같은 주소의 history 항목 하나를 쓴다(V3-P63). 답의 글은 `rich_text.js`가 HTML을 해석하지 않고 그린다. 서버는 평문 HTTP를 loopback에만 열고, 다른 기기는 TLS reverse proxy 뒤에서 쓴다.

## 2. 다른 앱

- **ChatGPT:** `/c/<id>`. 새로고침하면 그 대화가 열리고, 사이드바 항목은 링크라 새 탭에서 열 수 있다. 터치 기기에서는 Enter가 줄바꿈이고 보내기는 단추다. 답 아래에 복사 단추, 코드 블록 머리에 "Copy code".
- **claude.ai:** `/chat/<id>`. 답 아래 복사(마크다운 원문), 코드 블록 복사. 모바일 웹은 Enter = 줄바꿈.
- **Slack·Discord(웹):** 하드웨어 키보드에서는 Enter = 보내기, 모바일 화상 키보드에서는 Enter = 줄바꿈.

## 3. 주소

### 3.1 주소와 서버

| 화면 | 주소 |
| --- | --- |
| 홈 | `/` |
| 대화 | `/c/<대화 id>` |
| Files | `/files` |
| 휴지통 | `/trash` |
| 설정의 Instructions · Memory · Folders | `/settings/instructions` · `/settings/memory` · `/settings/folders` |

- 서버는 이 주소들의 `GET`에 `/`와 같은 `index.html`을 돌려준다. 대화 id는 `[A-Za-z0-9_-]{1,128}`만 받고, 그 밖의 주소는 지금처럼 404다. 응답에는 지금과 같은 보안 헤더·CSP가 붙는다(미들웨어가 같음). 로그인 전에도 `index.html`은 지금처럼 열린다(데이터는 API가 지킴).
- 정적 파일은 지금처럼 `/assets/…`의 절대 경로로 부르므로 `/c/…`에서도 그대로 불린다.

### 3.2 이동과 history

- **사용자가 고른 이동**(사이드바·홈의 대화, New chat으로 만든 대화, Home·Files·Trash·설정 단추)은 `history.pushState`로 항목을 하나 더한다. 같은 주소로의 이동은 더하지 않는다.
- **자동으로 바뀐 자리**(열려던 대화가 없음 → 홈, 휴지통으로 옮긴 대화 → 홈)는 `replaceState`로 바꾼다. 뒤로 가기가 없는 대화로 돌아가지 않게 하기 위해서다.
- **뒤로/앞으로**(`popstate`): 주소를 읽어 그 화면으로 간다(이때는 항목을 더하지 않는다).
  - 그 이동이 끝나면(떠나기가 거절됐든, 묻는 사이 다른 이동이 끼었든) **지금 항목의 주소를 실제로 보이는 화면의 것으로 바꾼다**(`replaceState`, 다를 때만). 그래서 주소창과 화면이 어긋나지 않고, 새로고침하면 보이던 화면이 열린다. `pushState`로 되돌리지 않는다: 항목이 늘거나 앞으로 갈 항목이 지워지기 때문이다(검수 B1). 거절된 뒤로 가기는 그 항목이 지금 화면의 주소를 갖게 되는 대신, 사용자에게는 "뒤로 가기가 취소됨"으로 보인다.
  - 로그인 화면이 떠 있는 동안의 뒤로/앞으로는 화면을 바꾸지 않는다. 주소는 로그인할 때 읽는다(검수 N5: 401 때 전체 화면 앱 화면을 닫는 `history.back()`, Sign out 뒤의 뒤로 가기).
  - 주소가 지금 화면과 같으면 아무것도 하지 않는다. MCP 앱 화면의 전체 화면 항목(V3-P63)은 **같은 주소**의 항목이라, 그 뒤로/앞으로는 지금처럼 `app_view.js`만 처리한다. 항목의 `state`는 앱 화면의 것(`himariAppView`)을 건드리지 않는다.
- 이동 함수(`openConversation`, `showHome` 등)가 주소를 직접 고치지 않는다. 화면이 실제로 바뀐 뒤 한 곳(`showSurface`)에서 "지금 화면의 주소"를 정하고, 이동의 종류(push / replace / 없음)는 부른 쪽이 넘긴다. 그래서 떠나기가 거절된 이동은 주소를 바꾸지 않는다.

### 3.3 페이지를 열 때와 로그인

- 페이지를 열면 주소를 읽어 둔다. 세션이 있으면 `enter()`가 홈 대신 그 화면을 연다. 홈이 아니면 사이드바 대화 목록도 홈처럼 읽는다(검수 N4). 없으면 로그인 화면을 보이되 **주소는 그대로 둔다**. 로그인하면 그 화면으로 간다.
- 세션이 끝나 로그인 화면으로 갈 때(401)도 주소는 그대로다. 다시 로그인하면 그 대화로 돌아온다. V3-P78의 초안도 그 자리에서 돌아온다.
- Sign out은 주소를 `/`로 바꾼다(`replaceState`). 공용 기기에 마지막 대화의 주소를 남기지 않기 위해서다.
- 그 대화가 없으면(휴지통·영구 삭제·다른 주체): 홈으로 가고 `replaceState("/")`, "That conversation is not here; it may have been moved to the trash."를 알린다. 이것은 새 동작이다: 지금은 대화를 열 때의 404를 오류 글로만 보이고, 폴링의 404만 홈으로 보낸다. `openConversation`의 오류 처리에서 하고, generation이 그대로일 때만 한다(늦은 404가 더 새 화면을 덮지 않게, 검수 N3).

### 3.4 탭 제목과 사이드바 링크

- `document.title`: 대화면 "<대화 이름> · HIMARI", 다른 화면이면 "Files · HIMARI"처럼, 홈은 "HIMARI". 이름이 바뀌면(첫 답 뒤 자동 제목, Rename) 따라 바뀐다.
- 사이드바와 홈의 대화 항목은 `<a href="/c/<id>">`가 된다(Q4).
  - 그냥 누르면 지금처럼 이 페이지 안에서 연다(`preventDefault`).
  - Cmd/Ctrl·Shift·가운데 단추로 누르거나, iPad에서 길게 눌러 "새 탭에서 열기"를 고르면 브라우저가 새 탭에서 연다. 새 탭은 같은 세션 쿠키로 바로 그 대화를 연다.
  - 모양은 지금 단추와 같게 둔다(밑줄 없음).

## 4. Enter

### 4.1 규칙

| 키 | 하드웨어 키보드 | 화상 키보드가 떠 있을 때 |
| --- | --- | --- |
| Enter | 보내기 | **줄바꿈** |
| Shift+Enter | 줄바꿈 | 줄바꿈 |
| Cmd/Ctrl+Enter | 보내기 | 보내기 |
| 한글 등 조합 중의 Enter | 무시(조합만 끝냄) | 무시 |

- **화상 키보드가 떠 있는지**는 `visualViewport.height × scale`이 창 높이(`window.innerHeight`)보다 150px 넘게 작은지로 본다(Q2; `scale`은 확대한 화면에서 하드웨어 Enter가 줄바꿈이 되지 않게, 검수 N1). iPad에 하드웨어 키보드를 붙이면 화상 키보드가 뜨지 않으므로 Enter가 그대로 보내기다(아래쪽 단축키 막대는 150px보다 작다).
- 이 페이지는 `interactive-widget=resizes-content`를 쓰므로 Android의 Chromium·Firefox에서는 창 자체가 줄어 위 비교가 늘 0이다. 그래서 터치가 주 입력인 기기(`(hover: none) and (pointer: coarse)`)에서는 **같은 창 너비에서 본 가장 큰 창 높이보다 150px 넘게 작으면** 화상 키보드로 본다. 키보드는 높이만 줄이고, 화면을 돌리거나 창 크기를 바꾸면(Stage Manager) 너비도 바뀐다. iPadOS는 돌려도 `screen`의 가로·세로를 바꾸지 않으므로 방향으로 나누지 않는다(PR #108 검수 B1). `visualViewport`가 없으면 터치가 주 입력인 기기에서 줄바꿈으로 본다.
- 한계(실기기 확인 목록에): iPad의 떠 있는(floating)·나뉜 키보드는 화면을 줄이지 않아 Enter가 보내기가 되고 줄바꿈은 Shift가 없어 넣을 수 없다. Stage Manager 창은 키보드에 일부만 가려 150px보다 덜 줄 수 있다.
- **조합 중:** `event.isComposing` 또는 `event.keyCode === 229`이면 Enter를 처리하지 않는다. Safari는 조합을 끝내는 Enter에 `isComposing=false`·`keyCode=229`를 주기 때문이다. 프롬프트 선택 창의 Enter(고르기)도 같은 규칙을 쓴다. 기본 동작을 막지 않으므로 Safari가 조합을 끝내며 줄바꿈을 넣을 수 있다(그러면 다음 Enter가 끝에 빈 줄이 붙은 글을 보냄; 보내기가 앞뒤 공백을 지우므로 보이는 차이는 없음). 실기기에서 확인한다(검수 N2).
- 프롬프트 선택 창이 열려 있을 때의 Enter(고르기)는 지금 그대로다.

### 4.2 보이는 것

- 화상 키보드가 떠 있을 때는 보내기 단추가 유일한 보내기라, 단추의 크기(44px 이상)를 확인한다. 안내 글은 더하지 않는다(ChatGPT와 같음).

## 5. 복사

- **끝난 답:** 답 아래에 작은 "Copy" 단추(아이콘 + 글). 누르면 그 답의 **원문(마크다운)**을 복사한다(Q3). 원문은 화면이 그린 Event의 `text` 그대로다. 수식·코드·목록이 원래 쓰인 대로 남아, 다른 곳(문서, 다른 채팅)에 붙였을 때 다시 그릴 수 있다.
- **코드 블록:** 블록 오른쪽 위에 "Copy". 블록 안의 코드만 정확히(펜스·언어 표시 없이) 복사한다. **쓰는 중인 답(스트리밍)에는 없다**: `live.js`가 0.1초마다 다시 그려 누르는 사이 단추가 바뀌고 "Copied"도 사라지기 때문이다(검수 B2). 답이 끝나 Event로 바뀌면 생긴다. 이 단추는 `renderAssistantText`의 선택 사항이라, 한 줄 요약(`assistantTextLine`)과 작업 묶음의 진행 글에는 붙지 않는다.
- **눌렀을 때:** 단추 글이 2초 동안 "Copied"가 된다. 실패하면 상태 줄에 "Couldn't copy; select the text instead."
- **방법:** `navigator.clipboard.writeText`(HTTPS 또는 loopback에서만 됨; HIMARI는 둘 중 하나로만 열림). 없거나 거부되면 보이지 않는 `textarea`를 골라 `document.execCommand("copy")`로 한 번 더 해 본다.
- **보이는 방식:** 터치 기기에는 hover가 없으므로 늘 보인다. 흐린 색으로 두어 답을 가리지 않는다.
- 쓰는 중인 답 전체, 멈춘(흐린) 답, 사용자 메시지에는 답 복사 단추를 두지 않는다. 사용자 메시지는 수정·다시 보내기 패킷에서 함께 다룬다. 질문(`ask_user`)과 그 앞 글도 답처럼 그려지므로 Copy가 붙는다(해가 없고 ChatGPT와 같음, 검수 N7).
- 단추 글은 `user-select: none`이라, 답을 손으로 고르거나 전체 선택해도 "Copy"가 섞이지 않는다(검수 N7).
- 안전: 복사하는 것은 화면이 이미 보이는 글이고, 클립보드 읽기는 하지 않는다. `rich_text.js`의 규칙(HTML을 해석하지 않음)은 그대로다. 단추는 `textContent`로만 만든다.

## 6. 계약 변경 (Proposed)

- Web 서버: `GET /c/{id}`(id `[A-Za-z0-9_-]{1,128}`), `/files`, `/trash`, `/settings/{instructions|memory|folders}`가 `index.html`을 돌려준다.
- Web 화면: 위의 동작. API·Data·Provider·runner·CLI는 그대로.

## 7. 위협과 대응

| 위협 | 대응 |
| --- | --- |
| 주소의 id로 남의 대화를 엶 | 주소는 화면만 고르고, 데이터는 지금처럼 API가 주체를 확인(없으면 홈 + 알림) |
| 주소 경로로 서버 파일에 닿음 | 정해진 경로만, id는 문자 집합 제한, 응답은 늘 같은 `index.html` |
| 공용 기기의 history에 대화 id·이름이 남음 | Sign out이 지금 항목의 주소를 `/`로; 앞선 항목과 탭 제목으로 남은 대화 이름은 브라우저 기록의 것(지우기는 사용자). 다른 탭의 로그아웃 알림을 받은 탭은 주소를 바꾸지 않는다(그 탭의 로그인 화면이 주소를 지킴; 검수 N8) |
| 뒤로 가기로 저장 안 한 글을 잃음 | `mayLeave`가 지금처럼 묻고, 거절하면 주소를 되돌림 |
| 복사 단추가 남의 글을 클립보드에 넣음 | 사용자가 누를 때만, 보이는 글만 |

## 11. 구현 노트 (2026-10-26)

- **서버:** `SURFACE_PATHS`의 다섯 경로와 `GET /c/{id}`(`PAGE_ID`)가 `index`와 같은 응답(테스트 `test_surface_addresses_are_the_page`: 헤더 같음, 잘못된 id·다른 경로는 404).
