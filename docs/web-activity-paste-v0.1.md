>
> 소유자 방향(2026-10-26): Web UX 점검의 세 번째 묶음. 원래 묶음의 "메시지 수정·다시 보내기·다시 생성"은 기록(Data의 Event가 쌓이기만 함)·압축 요약·Prompt·Control에 걸친 설계라 다음 패킷(V3-P81)으로 떼고, 이 패킷은 **다른 대화가 무엇을 하는지 보이기**와 **붙여넣기로 첨부하기**를 다룬다.

> 앞선 결정: 대화 한 개의 상태는 `GET /api/conversations/{id}`가 알려 주고, 그 읽기는 "사용자가 보고 있음"으로 센다(V3-P62 §5, `application.seen`). 열린 대화만 1초마다 확인한다. 올린 파일은 대화별로 서버에 먼저 두고(V3-P66), 입력창은 자리마다 초안을 둔다(V3-P78). 메시지는 32,000자까지다.

## 2. 다른 앱

- **ChatGPT:** 사이드바에서 답을 쓰는 중인 대화에 표시가 돈다. 스크린샷·파일을 붙여넣으면 첨부가 되고, 아주 긴 글을 붙여넣으면 "Pasted text" 첨부로 바뀐다.
- **claude.ai:** 긴 붙여넣은 글은 "Pasted" 첨부 카드가 된다. 이미지 붙여넣기는 첨부.
- **Slack:** 사이드바 채널 옆 표시(안 읽음·멘션 수), 탭 제목에 수 `(3) Slack`.

## 3. 다른 대화의 상태

### 3.1 무엇을 보이나 (Q1)

| 상태 | 사이드바 | 뜻 |
| --- | --- | --- |
| 일하는 중 | 제목 오른쪽에 천천히 깜빡이는 점(테마의 강조색), `title`/`aria-label` "Working" | 그 대화의 job이 돌고 있음 |
| 답을 기다림 | 채운 점(경고색), "Waiting for your answer" | 마지막 Run이 `ask_user`를 하나 남기고 기다림 |
| 그 밖 | 없음 | |

- 열린 대화의 항목에도 같은 표시가 붙는다(상단의 상태와 같은 뜻).
- 홈의 "최근 대화" 카드에도 같은 점.
- 움직임을 줄이는 설정(`prefers-reduced-motion`)이면 깜빡이지 않는다.

### 3.2 서버: 한 번에 읽는 활동 (Q3)

- 새 읽기 `GET /api/conversations/activity` → `{ "working": [id…], "waiting": [id…] }`. 그 주체의 휴지통 밖 대화만. 경로는 `/api/conversations/{conversation_id}`보다 **먼저** 등록한다(아니면 `activity`가 대화 id로 잡혀 404, 검수 N1).
  - `working`: Control의 Runner가 지금 job을 돌리는 대화. Runner 공개 계약(`ConversationRunner`)에 `running(principal) -> Sequence[ConversationId]`를 더한다. `status`처럼 동기이고, 메모리에 있는 job(보내기·이어 가기·압축·취소 모두 같은 자리)을 읽을 뿐이다.
  - `waiting`: Data의 새 읽기 `list_waiting_conversations(principal) -> Sequence[ConversationId]`(`ConversationCatalog`: 주체 전체를 읽고 휴지통을 빼는 읽기가 있는 곳, 검수 N8). 지금 대화 하나에 대해 하는 `find_waiting_call`과 같은 규칙(마지막 PROJECTED Run의 Tool 실행이 `ask_user` 하나이고 PENDING)을 그 주체의 모든 대화에 한 번의 질의로. 스키마 변경 없음(SQLite와 인메모리 둘 다).
- 이 읽기는 **"보고 있음"으로 세지 않는다**(`application.seen`을 부르지 않음). 자리 비움 정지(V3-P62)가 사이드바 때문에 꺼지면 안 되기 때문이다.
- 한 번의 응답은 작다(일하는·기다리는 대화만). 대화 목록 자체(`GET /api/conversations`)는 바꾸지 않는다.

### 3.3 화면이 읽는 때

- 페이지가 보이는 동안 **5초마다** 읽는다. 숨겨지면(`visibilitychange`) 멈추고, 다시 보이면 바로 한 번 읽는다.
- 열린 대화의 상태가 바뀌면(1초 폴링이 job 끝을 봄) 바로 한 번 더 읽는다.
- 받은 것은 앱 상태(`app.activity`)에 두고, 사이드바·홈 카드는 그것으로 점을 그린다. 목록이나 홈 카드를 다시 그릴 때(job이 끝날 때의 목록 다시 읽기, 대화 만들기, 홈)도 그 상태로 다시 그리므로 점이 사라지지 않는다(검수 N2). 활동 읽기 때문에 목록을 다시 불러오지 않으므로 "Load more"로 본 항목과 스크롤이 그대로다.
- 사이드바에 없는 대화가 `working`·`waiting`에 있으면(다른 탭·CLI에서 새로 만들었거나, 목록 첫 쪽보다 오래된 대화) **그 id마다 한 번만** 목록을 새로 읽는다. 오래된 대화는 활동 순서로 맨 위에 오지 않으므로, 한 번만이어야 5초마다 다시 읽는 일이 없다(검수 B1). 그 대화는 "Load more"로 찾을 수 있고, 탭 제목의 수에는 들어간다.
- 목록 읽기는 마지막 것만 그린다: 다시 읽기와 "Load more"가 겹쳐도 줄이 겹치거나 뒤섞이지 않는다(검수 N2).
- 활동 읽기도 마지막 것만 쓴다: 먼저 보낸 읽기의 늦은 답이 나중 것을 덮지 않는다(검수 N3).
- 열린 대화에서 보내기·답하기가 받아들여지면 바로 한 번 더 읽는다(검수 N10).
- 401이면 지금처럼 로그인 화면(V3-P78 §6, 반복 401은 토큰 칸을 지우지 않음). 로그인 화면에서는 읽지 않는다.

### 3.4 탭 제목 (Q2)

- 답을 기다리는 대화가 있으면 탭 제목 앞에 수를 붙인다: `(2) Seoul trip · HIMARI`. 지금 열린 대화도 센다(탭이 뒤에 있을 때 보이게). 제목은 V3-P79의 한 곳(`followTitle`)이 상단 제목과 **저장한 수**로 만든다. `document.title`에 앞붙이지 않으므로 `(1) (1) …`이 되거나 상단 제목이 바뀔 때 수가 사라지지 않는다(검수 N4).
- 일하는 중은 세지 않는다(자주 바뀌어 제목이 깜빡거림).

## 4. 붙여넣기

### 4.1 파일 (Q4)

- 입력창의 `paste`에서 `clipboardData.files`(없으면 `items` 중 `kind === "file"`)를 본다.
- **파일이 있고 평문(`text/plain`)이 없으면**: 기본 동작을 막고 그 파일들을 첨부한다(지금의 `addFiles` — 홈이면 대화를 만들고, 만드는 중이면 기다림; V3-P78 §3.1). iPad 스크린샷, Finder에서 복사한 파일, 브라우저에서 "이미지 복사"가 이 경우다.
- **평문도 있으면**: 글만 붙인다(기본 동작). 문서 앱에서 서식 있는 글을 복사하면 글과 그림이 같이 오는데, 사용자가 원한 것은 대개 글이다.
- 이름이 없거나 흔한 기본 이름(`image.png`, `image.jpg` 등)이면 `pasted-<YYYYMMDD-HHMMSS>[-n].<확장자>`로 바꿔 올린다(여러 장을 붙여도 구분됨; 올리기는 파일 이름을 그대로 쓰므로 `new File([원래], 새 이름, {type})`로 만든다). 확장자는 MIME에서(`image/png` → `png`, 모르면 `bin`).
- 확인할 것(실기기, 검수 N7): Finder에서 복사한 파일은 파일 이름을, 브라우저의 "이미지 복사"는 주소를 평문으로 같이 둘 수 있다. 그러면 위 규칙상 글이 붙는다. iPadOS 사진 앱과 함께 확인한다.
- 크기·종류 한도와 오류는 지금의 첨부와 같다(서버가 판단).

### 4.2 너무 긴 글 (Q4)

- 붙여넣은 평문 때문에 입력창이(고른 부분을 붙여넣은 글로 바꾼 결과가, 서버처럼 코드 포인트로 세어, 검수 N5) **32,000자를 넘게 되면**, 그 글을 입력창에 넣지 않고 `pasted-<YYYYMMDD-HHMMSS>.txt`(UTF-8) 첨부로 올리고 알린다: "The pasted text was long, so it was attached as a file." 입력창의 원래 글은 그대로다.
- 32,000자 이하면 지금처럼 글로 붙는다. 입력창이 이미 한도를 넘었으면 무엇을 붙여넣든 파일이 된다.
- 명령을 실행할 수 없는 서버에서 올리기가 끝나면 "PDF·그림은 못 읽음" 경고가 나오는데, 평문 파일(`text/plain`)에는 내지 않는다(위 알림을 덮지 않게, 검수 N6). HTML 등 다른 글 파일은 지금처럼 경고한다.
- 모델은 그 파일을 첨부 파일로 받는다(지금 텍스트 파일 첨부와 같음: 명령 실행이 없어도 텍스트 파일은 읽음).

## 5. 계약 변경 (Proposed)

- Data(`ConversationCatalog`): `list_waiting_conversations(principal: PrincipalId) -> Sequence[ConversationId]`. SQLite·인메모리 구현, 스키마 변경 없음.
- Control(`ConversationRunner`): `running(principal: PrincipalId) -> Sequence[ConversationId]`(동기).
- Web API: `GET /api/conversations/activity`(`seen`을 부르지 않음).
- Web 화면: 위의 동작. Provider·runner(machine)·CLI는 그대로.

## 8. 검증 계획

- 공개 계약(Data·Control 하위 포트, Web API)이 바뀌므로 **전체 pytest**(`docs/testing-policy.md`, 검수 N9).
- Data: `list_waiting_conversations` — 질문 대기, 답한 뒤 없음, Tool 둘이면 아님, 질문 뒤에 PROJECTED가 아닌 새 Run이 있어도 기다림(`find_waiting_call`과 같음), 다른 주체·휴지통 제외(SQLite·인메모리 둘 다).
- Runner: `running` — job이 도는 동안만, 주체별.
- Web API: `activity`가 `seen`을 부르지 않음(자리 비움 계산이 바뀌지 않음), 401.
- 브라우저(`ui_smoke`, 새 시나리오 `activity`):
  1. 대화 A가 일하는 동안 B를 열면 사이드바 A에 일하는 중 표시, 끝나면 사라짐.
  2. A가 질문하면 A에 기다림 표시와 탭 제목 `(1)`, 답하면 사라짐.
  3. 다른 탭에서 새로 만든 대화가 일하면 이 탭의 목록에 나타남.
  4. 이미지 붙여넣기 → 첨부 칩(`pasted-….png`), 글과 이미지를 같이 붙여넣기 → 글만.
  5. 32,000자 넘는 글 붙여넣기 → `.txt` 칩과 알림, 입력창 원래 글 그대로.
- iPad 실기기(소유자): 스크린샷 붙여넣기, 사진 앱에서 복사한 사진.

## 10. 구현 노트 (2026-10-26)

- **Data:** `ConversationCatalog.list_waiting_conversations` — SQLite는 대화마다 PROJECTED이고 Event가 있는 Run의 `MAX(seq)`를 고른 뒤 그 Run의 Tool 실행이 하나뿐이고 PENDING `ask_user`인지 보는 질의 하나(`runs_by_conversation` 색인), 인메모리는 `_waiting`을 대화마다. 계약 테스트(두 백엔드): 주체·휴지통·답함·Tool 둘·질문 뒤 새 Run, 그리고 대화별 `find_waiting_call`과 같은 답.
