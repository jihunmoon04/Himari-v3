# 페르소나 항목 나누기 v0.1 (캐릭터 로드맵 7단계, 2026-11-25)

[캐릭터 로드맵](character-architecture.md) 7단계. [반려 페르소나](companion-persona-v0.1.md)의 글 하나짜리 페르소나를 항목으로 나눈다. 소유자 방침(2026-11-25)에 따라 짧게 정하고 써 보며 고친다.

## 1. 왜

- 지금 페르소나는 글 하나다. 첫 양식(§6.3)이 줄머리로 안내하지만 사용자가 무엇을 어디에 써야 하는지 분명하지 않다. 소유자: "말투, 성격 등을 명확하게 나누어 사용자가 적절한 형식으로 입력할 수 있도록".
- 6단계 작업([작업 설계](character-work-v0.1.md))은 **HIMARI가 무엇을 만드는지**를 페르소나에서 읽어야 한다. 따로 된 칸이 있으면 작가가 그것을 기준으로 프로젝트를 고른다.

## 2. 항목

| 칸 | 키 | 안내 |
| --- | --- | --- |
| 나와의 관계 | `relation` | 예: 오래 알고 지낸 친구 |
| 어디서 왔고 지금 어디에 있는지 | `world` | 세계 설정과 사용자 화면에 있는 까닭 |
| 나를 부르는 말 | `calls_user` | |
| 성격 | `personality` | |
| 말투 | `speech` | 반말/존댓말, 문장 길이, 자주 쓰는 표현 |
| 대사 예시 | `examples` | 한 줄에 하나, 3~5개. 말투에 가장 잘 듣는다 |
| 습관 | `habits` | |
| 좋아하는 것 / 싫어하는 것 | `likes` | |
| **하는 일과 만드는 것** | `makes` | 새 칸. 혼자 있을 때 하는 일, 만드는 것(예: 블랙홀 무기 설정집, 짧은 소설, 작곡). 6단계 프로젝트의 재료 |
| 하지 않는 것 | `never` | 예: 지나친 칭찬, 이모지 |
| 가까워지면 드러나는 이야기 | `familiar` | 관계 단계 Familiar부터 |
| 아주 가까워지면 드러나는 이야기 | `close` | 관계 단계 Close부터 |
| 자유 글 | `free` | 칸에 맞지 않는 것 모두 |

모든 칸은 비워 둘 수 있다. 페르소나 이름(목록에 보이는 이름)은 지금 그대로 따로다.

## 3. 저장과 모델에 가는 글

- 페르소나에 `fields`(JSON)를 더한다(스키마 v27, 6단계가 v26).
- **모델이 보는 글(`text`)은 저장할 때 항목에서 만든다.** 정해진 순서로 `칸 이름: 내용` 줄을 잇고(여러 줄 칸은 그 아래 줄들), `familiar`·`close` 칸의 줄에는 앞에 `[familiar]`·`[close]`를 붙인다. 그래서 숨긴 줄 거르기(`persona_for_stage`), 작가, 앱의 페르소나 메뉴는 바뀌지 않는다.
- 빈 칸은 글에 넣지 않는다. 같은 항목이면 같은 글이 나온다(캐시가 흔들리지 않게).
- **지금 있는 페르소나는 업그레이드 때 글 전체를 `free`에 넣는다.** 글이 그대로라 모델이 보는 것도 그대로다. 사용자가 원하면 칸으로 옮겨 적는다.
- API: 페르소나 읽기에 `fields`, 만들기·고치기는 `fields`를 받는다(`text`만 보내는 옛 요청은 `free`에 넣는 것으로 받는다). 글자 상한은 만든 글에 지금 상한을 그대로 건다.

## 4. 이야기 작가와 작업자

- 작가와 작업자 입력에 `makes`가 있으면 따로 준다(`persona_makes`). 작가 규칙: 프로젝트는 이 칸에서 고른다. 비었으면 페르소나 전체에서 어울리는 것을 고른다.

## 5. Web

- Settings → Personas의 편집 화면이 칸들로 바뀐다(위 순서, 칸마다 한 줄 안내, `examples`·`familiar`·`close`·`free`는 여러 줄).
- 칸으로 쓴 페르소나도 "모델이 보는 글" 미리보기를 접어서 보여 준다.
- 첫 양식(`STARTER`)은 칸의 안내 글(placeholder)로 옮긴다.

## 6. 정한 것(권고안대로, 써 보며 바꿈)

| # | 정한 것 |
| --- | --- |
| P1 | 칸 13개(§2), 새 칸 `makes` |
| P2 | 저장은 `fields`, 모델이 보는 글은 저장할 때 만든다. 숨긴 이야기 칸은 `[familiar]`·`[close]` 줄로 |
| P3 | 지금 페르소나는 `free`로 옮겨 모델이 보는 글이 바뀌지 않는다 |

## 7. 구현에서 정한 것 (2026-11-26, H-82, 배포 [기록](deployments/2026-11-26-v3-persona-fields.md))

- **칸은 14개다.** 설계의 13개 앞에 `name`(이름: HIMARI의 이름)을 더했다. 첫 양식의 첫 줄이 "이름:"이었고, 목록 이름은 모델에 가지 않으므로 캐릭터 이름을 쓸 칸이 따로 있어야 했다.
- **모델이 보는 글**(`data/rules.py` `persona_text`): 칸 순서대로 `칸 이름: 내용`(여러 줄이면 `칸 이름:` 다음 줄부터), `familiar`·`close`는 빈 줄을 빼고 줄마다 `[familiar] `·`[close] `(이미 붙은 표시는 한 번만), `free`는 맨 끝에 쓴 그대로. 한 줄 내용이 `[familiar]`·`[close]`(앞에 목록 표시가 있어도)로 시작하면 줄머리 다음 줄에 둬서 표시가 줄 앞에 남게 한다(검토). 줄은 `\n` 하나로 잇는다. `free`만 있으면 글은 `free` 그대로다(P3). 칸 이름은 첫 양식의 한국어 줄머리(`PERSONA_LABELS`).
- **검사**(`check_persona_fields`): 모르는 칸·글이 아닌 값은 `INVALID_ARGUMENT`, 칸마다 지시문과 같은 검사(줄바꿈 정리, 제어 문자 거부, 원래 길이로 `MAX_PERSONA_CHARS`), `free` 말고는 앞뒤 공백을 뗀다. 만든 글이 `MAX_PERSONA_CHARS`를 넘으면 `TOO_LARGE`.
- **저장**: 스키마 v27 `personas.fields`(JSON, 칸 순서). 업그레이드는 `json_object('free', text)`로 글 있는 페르소나를 `free` 하나로 옮긴다. `PersonaStore.create_persona`·`update_persona`가 `fields`를 받고(없으면 `text`가 `free`), `Persona.fields`가 칸들이다.
- **API**: `GET /api/personas`의 각 페르소나에 `fields`, 맨 위에 칸 순서 `fields`. `POST`·`PUT`은 `fields`(주면 `text`는 무시)나 옛 `text`. 거부 메시지에 "only the known fields"를 더했다. 앱(`/api/device/personas`)은 이름만 읽어 그대로다.
- **작가와 작업자**: `makes`가 있으면 `persona_makes`로 따로 준다. 그 안의 `[familiar]`·`[close]` 줄도 페르소나처럼 관계 단계까지 숨긴다(검토). 작가 지시문: "When persona_makes is given, start projects out of it."
- **Web**: 편집 화면은 칸들(이름·관계·세계·부르는 말은 한 줄, 나머지는 여러 줄), 첫 양식의 안내는 placeholder로 옮기고 `STARTER`는 없앴다. 접힌 "What HIMARI is told"가 서버와 같은 규칙으로 만든 글을 보이고(Python `strip`처럼 U+FEFF는 남김), 글자 수는 만든 글로 센다. 칸 하나가 원래 길이로 상한을 넘으면 Save가 꺼진다. 복제는 칸째 복사한다.
