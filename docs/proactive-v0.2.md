# 먼저 말 걸기 2단계: 잠들기, 다섯 가지 wake, 자유 wake (V3-P90 설계 초안 v0.2)

상태: **Proposed**, rev. 1. 소유자와 정한 내용(2026-11-02)을 정리한 초안. 소유자 결정 Q1~Q5(§14, Q2·Q3은 소유자 변경).

> 소유자(2026-11-02): "서버 쪽 말 거는 작업을 정리, 개정, 추가 하고 윈도우 앱의 동작을 이에 맞추자."
>
> 계기: V3-P87 운영 점검에서 둘이 드러났다. (1) 잠그지 않고 비웠다가 돌아오면 돌아옴 기록이 없다(`hub.py`의 돌아옴은 `unlock`·`resume`·`reconnect`뿐). (2) 앱은 무입력 5분에 잠들고 서버는 10분까지 지금 기기로 보므로, 그 사이에는 캐릭터가 자는 자세로 말한다.

앞선 결정
- **V3-P87(먼저 말 걸기, [proactive-v0.1.md](proactive-v0.1.md)):** `wake` 이벤트, `begin_wake`, 사용자가 이김, 알림의 `scheduled → claimed → delivered / missed`, 정리된 대화에서만, `speaks_first` 모델만. **이 문서는 그 길을 그대로 쓰고 계기와 조절 규칙을 바꾼다.**
- **V3-P88(활동 신호, [activity-signals-v0.1.md](activity-signals-v0.1.md)):** 앱이 보내는 통째 스냅샷(`session`, `activity`, `media`, `mic_or_camera`), 잠긴 기기는 지금 기기가 아님, `after`(`unlock`·`resume`)는 60초 흔들림 막기를 넘음, 직전 활동 `before`.
- **V3-P86(애니메이션):** 잠들기(하품 → `sleep` 반복), 깰 때 `stretch`. 지금 기준은 무입력 300초(`MainWindow.xaml.cs`).
- **V3-P84(화면):** 화면은 사용자가 보낼 때만 붙는다. 모델이 스스로 보는 화면은 다음 단계(화면 tool).

## 1. 무엇이 바뀌나

| | V3-P87 (지금) | 이 문서 |
| --- | --- | --- |
| 잠들기 | 앱 혼자, 무입력 5분 | **앱이 정하고 서버에 알림** (`sleep`), 무입력 10분·화면 꺼짐·잠금, 조용한 활동 중에는 안 잠 |
| 지금 기기 | 연결 + 잠금 아님 + 10분 안 입력 | 연결 + 잠금 아님. **잠든 기기도 지금 기기** |
| 돌아옴 | 잠금 해제·깨어남·다시 연결, 20초 기다림, 4시간 | **잠에서 깸**, 바로(기지개 뒤), **1시간** |
| 오래 집중·게임 끝남 | 분류 30분, 게임 끝남 30분 | **자유 wake**(작업이 이어짐, 15 → 30 → 60분)와 **작업 끝남**(게임·영상 1시간) |
| 조절 규칙 | 8개를 거의 모든 계기에 | **wake마다 꼭 맞는 것만.** 간격·예산은 자유 wake(와 고리의 간격)에만 |
| pass | 없음 | 자유 wake만 "말하지 않음"을 고를 수 있음 |

**하지 않는다(뒤 단계):** 화면 tool과 그것을 자유 wake에 붙이기(§10은 자리만), 금액 단위의 비용 상한(§7.4), Web만 쓰는 사용자에게 말 걸기, 앱이 꺼져 있을 때 알리기.

## 2. 잠들기 (앱)

### 2.1 잠드는 때

- **무입력 10분**(지금 5분에서 바꿈. 서버의 옛 기준 `CANDIDATE_SECONDS`와 같다)
- **화면이 꺼짐**(`GUID_CONSOLE_DISPLAY_STATE`가 off)
- **잠금**(`SessionSwitch`의 lock). 소유자 목록에는 없지만, 잠금은 자리를 뜬다는 분명한 행동이고 잠금 화면 뒤에서 캐릭터가 깨어 있을 까닭이 없어 더했다(§14 Q1).
- **절전**은 앱이 돌지 않는다. 깨어나면 앱은 잠든 채로 이어 간다(§2.3).

### 2.2 조용한 활동: 잠들지 않음

아래 가운데 하나라도 있으면 무입력 10분이 지나도 잠들지 않는다. 신호가 없는 경우(웹 글 읽기 등)는 잠들 수 있다.

| 활동 | 판단 |
| --- | --- |
| 영상·음악 재생 | Windows 미디어 세션이 재생 중 |
| 통화 | 마이크나 카메라를 쓰는 중(V3-P88 §6.1의 판정, 빼는 목록 포함) |
| 전체 화면 | 앞 창이 모니터 전체를 덮음 |

- 이 판단은 **앱 안에서만** 한다. 사용자가 "재생 중인 미디어 보내기"나 마이크·카메라 신호를 꺼 두었어도 잠들기 판단에는 쓰고, 서버에는 보내지 않는다.
- 화면 꺼짐과 잠금은 조용한 활동보다 앞선다(영상을 틀어 둔 채 잠그면 잠든다).

### 2.3 깨어나는 때

- **잠금 해제:** 바로 깬다. 비밀번호를 친 것은 사람이 앉았다는 분명한 행동이다.
- **그 밖(무입력, 화면 꺼짐 뒤, 절전 뒤, 앱이 막 시작함):** 입력이 처음 보이고 **5초가 지난 뒤 다시 입력이 보이면** 깬다(소유자 결정 2026-11-02, Q2). 책상을 치거나 마우스가 밀린 한 번의 입력을 거른다.
  - 확인하는 입력은 처음 입력에서 5초 뒤부터 15초 안에 보여야 한다. 그 안에 없으면 확인을 버리고, 그 뒤의 입력을 새 처음 입력으로 본다.
  - 처음 5초 안의 입력은 세지 않는다(한 번 밀린 마우스가 여러 이벤트를 낸다).
  - **예외: 키보드 입력이나 히마리 창을 누름**은 바로 깬다(사용자가 말을 걸려는 것이다).
- 깨면 `stretch`를 재생한다(이미 있는 그림, `CharacterAnimator.SetSleeping`).
- **앱이 시작할 때는 잠든 상태로 시작한다.** 그래서 PC를 켜고 처음 조작하는 순간이 "잠에서 깸"이 된다. 비운 시간은 서버가 DB의 마지막 입력으로 재므로 꺼져 있던 시간이 들어간다(§4.2). 앱만 다시 시작했으면 마지막 입력이 방금이라 인사가 되지 않는다.

### 2.4 알림으로 잠깐 깸

- 잠든 기기에 알림 wake가 오면(§5.1) 앱은 **잠깐 깬다**: 눈을 뜨고 말하고, 말풍선이 사라지면 다시 잠든다.
- 그동안 서버에 보내는 `sleep`은 **바꾸지 않는다**(사용자가 돌아온 것이 아니다).
- 그 사이 사용자가 조작하면 §2.3의 확인을 거쳐 진짜 깨어남이 된다. 다만 서버는 **알림이 말한 뒤 10분 안**의 깨어남에는 돌아옴 인사를 하지 않는다(§5.2). 사용자는 방금 뜬 알림에 답하려는 것이다.

## 3. 서버: 지금 기기와 잠

### 3.1 신호 (앱 → 서버)

`POST /api/device/presence`의 통째 스냅샷(V3-P88 §2.1)에 더한다.

```json
{"idle_seconds": 4, "session": "active",
 "sleep": null,
 "task": {"group": "work", "for_seconds": 2710},
 "task_ended": null,
 "activity": {...}, "media": {...}}
```

| 필드 | 값 | 뜻 |
| --- | --- | --- |
| `sleep` | `null` | 깨어 있음 |
| | `"idle"` | 무입력으로 잠듦(화면은 켜져 있을 수 있음) |
| | `"display_off"` | 화면 꺼짐으로 잠듦 |
| `task` | `{group, for_seconds}` 또는 `null` | 이어지는 작업(§6.1). 없으면 `null` |
| `task_ended` | `{group, lasted_seconds, ended_seconds_ago}` 또는 `null` | 방금 끝난 게임·영상(§5.3). 3분 동안 실림 |

- 잠금은 지금처럼 `session: "locked"`(그때 `sleep`은 보내지 않아도 된다. 잠긴 기기는 지금 기기가 아니다).
- 보내는 때: `sleep`이 바뀌면 **바로**(깸은 확인이 끝난 순간). `task`의 묶음이 바뀌거나 `task_ended`가 생기면 바로. 그 밖에는 지금처럼 60초마다.
- **호환:** 서버가 `hello`의 `features`에 `"sleep_signals": 1`을 줄 때만 앱이 새 필드를 보낸다(V3-P88의 `presence_signals`와 같은 방식). 새 필드가 없는 앱(옛 앱)에는 지금의 규칙(10분 안 입력, `unlock`·`resume`·`reconnect` 돌아옴)을 그대로 쓴다.

### 3.2 지금 기기 (`PresenceHub._decide`)

- 후보: 연결됨 + 잠금 아님. **`sleep` 신호를 보내는 기기는 잠들어 있어도 후보**이고, 10분 입력 조건(`CANDIDATE_SECONDS`)을 보지 않는다. 옛 앱은 지금처럼 10분 조건.
- 고르기는 지금과 같다: 가장 늦은 입력, 60초 흔들림 막기, `after`가 붙은 기기는 바로.
- 그래서 PC 한 대를 쓰는 사용자는 잠금·연결 끊김이 아니면 늘 지금 기기가 있다. 말을 걸지는 wake마다 `sleep`을 보고 정한다(§5).
- `DeviceState`에 `sleep`, `task`, `task_ended`를 더한다(메모리에만, V3-P88과 같음).

### 3.3 돌아옴 기록

- `sleep` 신호를 보내는 기기는 **잠듦 → 깸**(`sleep`이 `"idle"`·`"display_off"`에서 `null`로)이 돌아옴이다. `Returned(device_id, at, via)`의 `via`는 `"wake"`, 같은 신호에 `after: "unlock"`이 붙었으면 `"unlock"`.
- `after: "resume"`은 지금 기기를 넘겨받는 데만 쓰고 돌아옴을 만들지 않는다. 절전 뒤의 앱은 잠든 채이고, 사용자가 조작해 깨면 그때 돌아옴이 된다.
- `reconnect` 대비 경로는 첫 신호가 깨어 있는 기기에만 남긴다(서버를 다시 시작한 경우. 비운 시간이 짧아 인사가 되지 않는다).
- 비운 시간은 지금과 같다: 돌아옴 시각 − 모든 기기의 마지막 입력 중 가장 늦은 것(Data `devices.last_input_at`, 10분 단위). 잠든 동안에는 입력이 없으므로 잠든 시간과 PC가 꺼진 시간이 모두 들어간다.

## 4. wake 다섯 가지

| wake | 계기 | 이유(`WakeReason`) |
| --- | --- | --- |
| 알림 | `remind_at`이 됨 | `reminder` (그대로) |
| 돌아옴 | 잠에서 깸, 비운 시간 1시간 이상 | `returned` (`via: "wake"` 더함) |
| 작업 끝남 | 1시간 넘게 한 게임·영상이 분명히 끝남 | **`task_ended`** `{group, minutes}` (새) |
| 열린 고리 | 기한 +1시간, 날짜만이면 18시 | `loop_due` (그대로) |
| 자유 wake | 같은 작업이 이어짐: 15 → 30 → 60분 | **`free`** `{group, minutes, step}` (새) |

- `focus`와 `game_ended`는 더 만들지 않는다. 이미 기록된 wake의 이유는 지금처럼 읽고 그린다(enum 값을 남김).
- 같은 때에 여러 개가 맞으면 지금처럼 한 wake로 합친다(§6.4 of V3-P87, 순서: 알림 → 고리 → 작업 끝남 → 자유 → 돌아옴, 4개까지). **합친 wake에 `free`가 아닌 이유가 하나라도 있으면 pass할 수 없다**(§7.3).

## 5. 조절 규칙: wake마다

**모든 wake에 공통(줄이지 않음):** `HIMARI_PROACTIVE`와 `HIMARI_COMPANION`이 켜짐, 대화 모델이 `speaks_first`(자유 wake는 §7.5), 최근 대화가 정리됨(`accept_wake`가 lock 안에서 다시 확인), 지금 기기가 있음, 주체의 작업이 돌고 있지 않음.

| 조건 | 알림 | 돌아옴 | 작업 끝남 | 열린 고리 | 자유 wake |
| --- | --- | --- | --- | --- | --- |
| 잠듦 `idle` | **깨워서 말함** | (깬 순간이 계기) | 막힘 | 기다림 | 막힘 |
| 잠듦 `display_off`, 잠금, 연결 없음 | 기다림 → 늦은 알림 | — | 막힘 | 기다림 | 막힘 |
| 사용자의 "조용히" | 무시 | 막힘 | 막힘 | 막힘 | 막힘 |
| 23–08시 | 무시 | 무시 | 무시 | 막힘 | 막힘 |
| 최근 10분 안 사용자 메시지 | 무시 | 무시 | 막힘 | 막힘 | 막힘 |
| 답하지 않은 wake | 무시 | 무시 | 무시 | 막힘 | 막힘 |
| 마지막으로 말한 wake 뒤 15분 | 무시 | 무시 | 무시 | 막힘 | 막힘 |
| 하루 예산 | 무시 | 무시 | 무시 | 무시 | **있음**(§7.4) |
| 막혔을 때 | 24시간 안 기다림, 그 뒤 7일까지 돌아옴에 늦은 알림 | 3분 뒤 버림 | 3분 뒤 버림 | 24시간 안 기다림 | 작업이 이어지는 동안 기다림 |

### 5.1 알림

- 바뀌는 것은 하나: **`sleep: "idle"`인 기기에는 말한다**(앱이 잠깐 깸, §2.4). `display_off`·잠금·연결 없음이면 지금처럼 기다리고, 24시간이 지나면 돌아옴 때 늦은 알림(7일), 그 뒤 놓침.
- 그 밖(`scheduled → claimed → delivered / missed`, 3번 시도, 늦은 알림)은 V3-P87 §5.3 그대로.

### 5.2 돌아옴

조건(이것만):
- 지금 기기의 돌아옴 기록(§3.3)이 3분 안에 생김
- 비운 시간 ≥ `RETURN_HOURS`(**1시간**, 지금 4시간)
- 비운 동안 어느 대화에도 사용자 메시지가 없었음(Web·CLI로 말했으면 이미 돌아온 것)
- **돌아옴 전 10분 안에 말한 wake가 없음**(알림으로 잠깐 깬 뒤, §2.4)
- 사용자의 "조용히"가 꺼짐

없앤 것: 20초 기다림(`RETURN_WAIT`, 앱이 깸 확인(5초 뒤 다시 입력)을 이미 했다. 사용자가 바로 말을 걸면 V3-P87 §4.3의 "사용자가 이김"이 처리한다), 돌아온 기기 = 지금 기기 확인(깬 기기가 곧 지금 기기), 23–08시(사용자가 직접 PC를 깨웠다), 최근 10분 메시지("비운 동안 메시지 없음"과 겹친다), 답하지 않은 wake(오래 비웠다 돌아올수록 앞의 말에 답이 없을 가능성이 높아, 지금 규칙은 가장 필요한 때에 인사를 막는다), 간격, 하루 상한.

- 서버는 돌아옴 기록이 생기면 바로 판단한다(`on_returned` → `poke(0)`).
- 앱은 깨면서 기지개를 하고 있으므로 **기지개가 끝난 뒤** 말풍선을 연다(§9).

### 5.3 작업 끝남 (게임·영상)

- **계기:** 앱이 `task_ended`를 보냄. 앱은 끝이 분명할 때만 보낸다.
  - 게임: 게임 프로그램의 프로세스가 끝남
  - 영상: 미디어 세션이 멈추거나 닫히고 2분 동안 다시 재생되지 않음
  - 작업(`work`) 묶음의 끝은 보내지 않는다. 끝이 분명하지 않고, 대부분 잠듦으로 끝나 말할 사람이 없다.
- **조건:** 그 작업이 `ENDED_MINUTES`(**60분**) 이상 이어졌음, 끝난 지 3분 안, 깨어 있음, "조용히" 꺼짐, 최근 10분 안 사용자 메시지 없음.
- **미루지 않는다:** 막히면 3분 뒤 버린다. 9분 뒤에 "게임 끝났어?"는 어색하다.
- 간격·예산·23–08시·답하지 않은 wake를 보지 않는다. 끝남은 새로 생긴 일이다.
- 열쇠: `ended:<기기>:<끝난 시각, 분>`(±1분 별칭, 지금의 `game:` 열쇠와 같은 방식).

### 5.4 열린 고리

- 계기와 24시간 창은 V3-P87 §5.1 그대로.
- 바뀌는 것: 하루 상한을 보지 않고, 간격은 **마지막으로 말한 wake 뒤 15분**(돌아옴 인사 1분 뒤에 고리가 따로 나오지 않게). 잠든 동안은 기다린다(창 안에서 깨면 말함, 그때 돌아옴과 합쳐질 수 있음).

### 5.5 자유 wake

§6과 §7.

## 6. 작업이 이어짐 (앱)

### 6.1 작업 묶음과 주 작업

창을 여러 개 띄워 두거나 분할 화면으로 오가며 일해도 "한 작업"으로 보이게 한다.

| 묶음 (`group`) | 분류 |
| --- | --- |
| `work` | `coding`, `document`, `design` |
| `video` | `video` |
| `game` | `game` |
| 중립 | `browsing`, `chat`, `other`, 앞 창 없음 |

- 앱은 앞 창의 분류를 지금처럼 읽고, **최근 5분** 동안 묶음마다 앞에 있던 시간을 센다(초 단위, 메모리에만).
- **주 작업:** 중립을 뺀 시간이 2분 이상이고, 그 가운데 한 묶음이 절반을 넘으면 그 묶음. 없으면 주 작업 없음.
- **이어짐:** 주 작업이 같은 동안. `for_seconds`는 그 묶음이 주 작업이 된 때부터 센다. 중립은 작업을 끊지 않는다. 중립만 3분 넘게 이어지면 창에서 중립 밖 시간이 2분 아래로 떨어져 주 작업이 없어진다(자연스러운 유예).
- **창 길이(소유자 결정 2026-11-02, Q3):** 처음 권고 10분은 중립만 이어질 때 끝을 7분 늦게 알았다. 5분이면 3분이다. 더 줄이면 문서를 찾아 읽는 몇 분에도 작업이 끊긴다. 게임·영상의 끝(§5.3)은 이 창이 아니라 프로세스 종료·재생 멈춤으로 알므로 창 길이와 상관없다.
- **끝:** 주 작업이 다른 묶음으로 바뀜, 주 작업 없음, 잠듦.
- 히마리 창이 앞이면 직전 분류로 센다(V3-P88 §4.1과 같음).
- 사용자의 분류 바꾸기(앱 설정)는 그대로 적용된다. 묶음 표는 고정이다.

### 6.2 자유 wake의 타이머

- 단계: **15분 → +30분 → 그 뒤 +60분마다**(`FREE_STEPS = 15,30,60`, 마지막 값을 반복). 4시간 작업이면 15, 45, 105, 165, 225분.
- 다음 단계는 **마지막 상호작용**에서 센다: 작업 시작, 마지막 wake(어떤 종류든, pass 포함), 마지막 사용자 메시지 중 가장 늦은 것. 그래서 대화하던 중에는 다시 처음 간격부터다.
- 단계는 자유 wake가 열릴 때마다(말했든 pass했든) 하나 오른다. 작업이 끝나거나 바뀌면 처음으로.
- 막히면(§5 표) 작업이 이어지는 동안 기다렸다가 풀리면 한 번 연다. 밀린 단계를 몰아서 열지 않는다.
- 서버가 센다: 앱이 주는 것은 `task`뿐이고, 단계와 마지막 상호작용은 서버가 Data(wakes, 사용자 메시지)로 안다. 열쇠: `free:<기기>:<작업 시작 시각, 분>:<단계>`.

## 7. 자유 wake

### 7.1 모델에게 가는 것

화면 없이 **글로만** 연다(소유자 결정 2026-11-02. 화면은 §10).

```
<wake>{"reasons": [{"kind": "free", "task": {"group": "work", "minutes": 47}, "step": 2}],
       "device": "데스크톱"}</wake>
```

- 지금 하는 일의 자세한 것은 그 턴의 Current State `presence.now_doing`에서 본다(V3-P88 §7): 분류, 프로그램 이름, 이어진 시간, 전체 화면, 직전 활동, 재생 중인 미디어(켰을 때), 창 제목(켰을 때), 마이크·카메라. `now_doing`에 `task`(`group`, `for_minutes`)를 더한다.
- 대화 기록에는 앞선 wake와 그 말이 있으므로 모델은 같은 말을 되풀이하지 않을 수 있다(pass한 wake는 보이지 않는다, §7.3).

### 7.2 "Speaking first" 줄에 더함

반려 절의 `PROACTIVE_RULE`에 한 문장을 더한다(문장은 실제 모델 확인에서 다듬는다).

```
  A wake whose reasons are all "free" has no news: say something that fits what the user
  is doing, or answer exactly [[pass]] to stay silent when nothing fits or it is a bad
  moment (a call, a tense fullscreen game, the same thing you said last time).
```

- 이 문장은 `speaks_first`이고 자유 wake가 켜진 대화에만 들어간다(고정 문장, 캐시를 깨지 않음).

### 7.3 pass

- **판정:** 자유 wake 턴의 최종 답에서 표정 표시를 뗀 글이 정확히 `[[pass]]`이면 pass다. 다른 글과 섞여 있으면 `[[pass]]`를 떼고 나머지를 말한다.
- **흐름:** 서버는 자유 wake의 `live`에서 첫 글을 내보내기 전에 pass인지 가릴 수 있을 만큼(표정 표시 뒤 첫 글자) 쥐고 있다가 내보낸다. pass면 글을 하나도 내보내지 않고 작업을 끝낸다. 앱은 자유 wake의 말풍선을 **첫 글이 왔을 때** 연다(§9). 그래서 pass면 화면에 아무것도 생기지 않는다.
- **기록:** `wakes.status = "passed"`(스키마는 그대로, `status`는 글 열). wake 이벤트와 pass 답은 Data에 남지만 **어디에도 보이지 않는다**:
  - 모델 입력(Prompt), 압축 요약, 기억 작업, 대화 검색, Web·CLI·앱 기록에서 건너뛴다.
  - 그 이벤트를 건너뛰는지는 `wakes.status`로 정하므로, Loader가 기록 안의 `passed` wake 번호를 `PromptInputs`로 넘기고 **`context_key`가 해시한다**(V3-P87 §8.4의 `wake_notes`와 같은 방식). pass는 대화 끝에서 생기므로 캐시가 깨지는 곳은 끝 가까이다.
  - 답하지 않은 wake(§5)로 세지 않는다. 사용자가 그 뒤에 말해도 다음 Run의 계기에 넣지 않는다.
- **세기:** 하루 시도 수에는 세고, 말한 수와 15분 간격(§5)에는 세지 않는다. 타이머의 단계는 오른다(§6.2). 오르지 않으면 30초 뒤 다음 판단에서 바로 다시 부른다.
- **이벤트를 아예 쓰지 않는 길은 택하지 않는다:** Driver의 Run은 계기 이벤트가 있어야 하고(V3-001), 재시작·사용자가 이김·알림 상태가 모두 그 이벤트에 묶여 있다. 숨기는 쪽이 고칠 곳이 적다.

### 7.4 예산

| 항목 | 기본 | 설정 |
| --- | --- | --- |
| 하루에 말하는 자유 wake | **6** (pass 빼고) | `HIMARI_PROACTIVE_FREE_DAILY` |
| 하루에 여는 자유 wake | **12** (pass 포함, 비용 상한) | `HIMARI_PROACTIVE_FREE_ATTEMPTS` |
| 타이머 단계 | `15,30,60` | `HIMARI_PROACTIVE_FREE_STEPS` (빈 값이면 자유 wake 없음) |
| 간격(자유 wake와 고리) | **15분** | `HIMARI_PROACTIVE_GAP_MINUTES` (지금 30, 뜻이 바뀜) |

- 하루는 지금 기기의 시간대 자정부터(지금의 `local_midnight`).
- 어느 쪽이든 닿으면 그날 남은 자유 wake는 없다. 다른 wake에는 영향이 없다.
- **금액 상한은 두지 않는다(이번).** 요청 크기는 대화 길이와 캐시에 따라 크게 다르다. 대신 wake 작업의 Run 사용량(입력·캐시 읽기·출력 토큰, 이미 기록됨)을 wake별로 모아 `status`에 오늘의 자유 wake 수와 토큰 합을 보이고, 운영해 본 뒤 정한다.
- 지금의 `HIMARI_PROACTIVE_DAILY`(4)는 없앤다. 읽히면 시작 로그에 "무시됨"을 남긴다.

### 7.5 어느 모델에서

- pass를 고르는 판단은 V3-P87 §19.6의 실제 모델 확인에 없었다. **`ProviderCapabilities.free_wake`**를 따로 두고, 자유 wake 장면(말할 때, pass할 때: 통화 중, 전체 화면 게임, 방금 같은 말)을 실제 모델로 확인해 기준(80%)을 넘은 모델만 켠다.
- `speaks_first`이지만 `free_wake`가 아닌 모델의 대화에는 다른 wake만 연다(자유 wake 계기는 `model_unchecked`로 건너뜀, §7.2의 문장도 넣지 않음).

## 9. 앱 계약 (바뀐 부분)

- **잠들기·깨기:** §2. 잠들기 기준 600초, 화면 꺼짐·잠금, 조용한 활동, 깸 확인, 시작은 잠든 상태.
- **신호:** §3.1의 `sleep`, `task`, `task_ended`(서버의 `features.sleep_signals`가 있을 때만).
- **wake 작업이 이 기기에 올 때(`job`, origin `wake`):**
  - **잠들어 있음(알림):** 잠깐 깨서(눈 뜸, 기지개 없음) 말하고, 말풍선이 사라지면 다시 잠든다. `sleep` 신호는 그대로(§2.4).
  - **막 깨는 중(돌아옴):** 기지개가 끝날 때까지 받은 글을 쥐고 있다가 끝나면 말풍선을 연다. 모델의 첫 글자까지 1–3초 걸리므로 대개 기다림이 짧다.
  - **자유 wake:** 첫 글이 올 때 말풍선을 연다. 글 없이 작업이 끝나면(pass) 아무것도 보이지 않는다.
  - 대화 옮기기·상태 줄은 V3-P87 §19.10 그대로.
- **기록:** pass한 wake는 서버가 보내지 않는다(§7.3). `HistoryReader`는 바뀌지 않는다.
- **설정 창:** "자유 wake에 화면 보내기"(기본 끔). 이번에는 저장만 하고 서버에 `features`로 알린다. 쓰는 것은 화면 tool 때(§10).
- 가짜 기기 스크립트(`scripts/device_client.py`)에 장면을 더한다: 잠듦 → 알림 wake(잠든 채) → 깸 → 돌아옴 wake, `task`로 자유 wake → pass(글 없음), `task_ended`.

## 10. 화면 tool과 자유 wake (자리만, 이번에 구현하지 않음)

- 자유 wake는 글로만 연다. 모델은 pass, 말하기, **화면 보기 tool 부르기** 가운데 고를 수 있게 될 것이다. pass할 때는 화면을 찍지 않는다.
- 화면 tool(V3-P84 2단계)은 **그 자리에서 찍는 도구**로 만든다: 서버가 사건 흐름으로 그 기기에 요청하고, 앱이 지금처럼 찍어 올리고(`not_a_screen`, 크기 규칙 그대로), 도구 결과가 그 화면이다. 미리 찍어 두는 방식은 쓰지 않는다(쓰지 않은 화면이 올라가고, "화면 보냄" 표시가 모델이 보지 않았을 때도 뜬다).
- 자유 wake에 붙이는 조건: 앱 설정 "자유 wake에 화면 보내기"가 켜져 있을 때만 그 tool을 준다. 찍을 때는 지금처럼 말풍선에 화면을 보낸다고 표시한다.
- 화면 tool이 생기면 자유 wake의 Run 상한(지금 3)과 예산(시도 수)이 화면 한 번의 추가 Run을 감당하는지 그때 다시 본다.

## 11. Data

- **스키마는 바뀌지 않는다(v17 그대로).** `wakes.status`에 `passed`(글 열), `reasons` JSON에 `free`·`task_ended`, `via`에 `wake`.
- `WakeKind`에 `FREE`, `TASK_ENDED`. `WakeStatus`에 `PASSED`. codec은 모르는 값 없이 읽는다(옛 `focus`·`game_ended`도 계속 읽음).
- `spoke()`는 `PASSED`를 말한 것으로 세지 않는다. 오늘의 자유 wake 시도 수는 `wakes`에서 `free` 이유만 있는 줄을 센다.

## 13. 검증 계획

- **순수 규칙(`tests/proactive`):** §5 표의 칸마다(잠듦의 알림 말함·다른 wake 막힘, `display_off`의 알림 기다림, 돌아옴의 23–08시·답 없는 wake 무시, 알림 뒤 10분 안 돌아옴 없음, 작업 끝남 3분 뒤 버림, 고리의 15분 간격, 자유 wake 예산 6/12), 타이머 단계와 마지막 상호작용, 합친 wake의 pass 금지.
- **presence:** 잠든 기기가 지금 기기로 남음, 두 기기 중 잠든 쪽과 깬 쪽, 잠듦 → 깸이 돌아옴(`via: "wake"`), 잠금 해제 `"unlock"`, `resume`은 돌아옴 아님, 옛 앱은 지금 규칙 그대로.
- **runner/driver:** pass면 `live`에 글이 없고 `passed`, 섞인 `[[pass]]`는 떼고 말함, pass한 wake가 다음 요청·기억 작업·기록에 없음, `context_key`가 바뀜, `free_wake`가 아닌 모델은 자유 wake를 열지 않음.
- **앱(ContractTests, Linux):** 주 작업 계산(분할 화면처럼 `coding`·`browsing` 반반 → `work` 이어짐, 중립만 3분 넘게 → 끝), 깸 확인(5초 안의 입력은 세지 않음, 5–15초 사이 입력이면 깸, 없으면 처음부터, 키보드 바로), 조용한 활동, `task_ended`의 게임·영상 판단. **UiTests(Windows):** 알림으로 잠깐 깸 → 다시 잠듦, 기지개 뒤 말풍선, pass면 말풍선 없음.
- **실제 모델:** 자유 wake 장면(말함·pass)을 `tests/live/test_proactive_live.py`에 더하고 `free_wake` 목록을 정한다.
- **소유자 PC:** 잠그지 않고 1시간 비움 → 돌아와 조작 → 기지개 뒤 인사, 잠든 채 알림, 분할 화면 작업 15분 뒤 자유 wake.

## 15. 구현 단계

1. **서버 1(잠과 돌아옴):** `sleep` 신호와 `features.sleep_signals`, 지금 기기 후보, 돌아옴(`wake`), 돌아옴 조건 줄이기(§5.2), 알림의 `idle` 허용, 고리의 간격·하루 상한 변경. 옛 앱 호환 시험.
2. **앱 1:** 잠들기 600초·화면 꺼짐·잠금·조용한 활동, 깸 확인, 시작은 잠든 상태, `sleep` 신호, 알림으로 잠깐 깸, 기지개 뒤 말풍선.
3. **서버 2(작업):** `task`·`task_ended` 신호, 작업 끝남 wake, `focus`·`game_ended` 계기 빼기.
4. **앱 2:** 주 작업 계산, `task_ended` 판단.
5. **서버 3(자유 wake):** `free` 계기·타이머·예산, pass, `free_wake` 능력, 프롬프트 문장, 실제 모델 확인.
6. **앱 3:** 자유 wake 말풍선(첫 글에 열기), 화면 설정 저장.

1·2가 먼저 소유자의 두 문제(잠그지 않은 돌아옴, 잠든 채 말함)를 푼다. 3–6은 그 위에 쌓는다.
