# HIMARI Windows 앱

입력창에서 Enter는 전송, Shift+Enter는 줄바꿈이다. 말풍선 내용이 길면 스크롤해 읽을 수 있으며, 설정의 모든 탭도 작은 창에서 스크롤할 수 있다.

여러 줄 TextBox보다 먼저 처리하는 PreviewKeyDown에서 전송 키를 판별한다. IME 조합과 조합 확정 입력 중에는 전송하지 않는다. `dotnet run --project clients/windows/Himari.Companion.UiTests/Himari.Companion.UiTests.csproj`는 Windows의 숨겨진 WPF 창에서 라우팅 키 이벤트와 합성 조합 이벤트를 확인한다. 실제 한국어 IME 키보드 조작 시험은 별도로 필요하다.

PR 120에서 병합된 설계 rev. 5를 기준으로 만든 개발 중인 Windows 앱이다. .NET 10 Windows Desktop SDK가 필요하다. 서버 측 기기 API도 배포되어야 실제 연결할 수 있다.

```powershell
dotnet run --project clients/windows/Himari.Companion/Himari.Companion.csproj
```

Web의 Devices 화면에서 기기를 만들고, 앱 설정의 연결 탭에 HTTPS 서버 주소와 짝짓기 코드를 입력한다. 설정 창은 말풍선의 `⋯` 메뉴, 캐릭터 우클릭 메뉴, 트레이 메뉴에서 연다. 기기 토큰은 Windows 자격 증명 관리자에 보관한다. 캐릭터를 드래그하여 이동한다. 크기 슬라이더와 창 위치는 `%LOCALAPPDATA%\HIMARI\window.json`에 저장한다(토큰은 저장하지 않음). `Ctrl+Alt+H`는 앱과 대화 입력란을 연다. 다른 프로그램이 이 단축키를 이미 사용하면 트레이 메뉴로 앱을 열 수 있다. 트레이의 보이기/숨기기·설정·다시 연결·Web 열기·종료를 사용할 수 있다. 이미지들은 `animation-preview/pixel`에 있는 실험용 생성 시안이다.

입력창에서 `화면 첨부`를 선택하거나 트레이의 `화면 같이 보기`를 켜면 전송 시 모니터를 캡처한다. 이 기능은 V3-P84 서버 계약이 필요하며, 트레이의 같이 보기 선택을 끌 때까지 메시지마다 화면을 보낸다. 설정에서 캐릭터 이동을 끌 수 있고 `이동 미리보기`로 현재 이미지가 움직이는 모습을 볼 수 있다. 이동 중 직접 드래그하면 원래 위치로 돌아가지 않는다.

화면 전송과 이동은 서버 PR #126의 계약을 기준으로 구현했다. 글 전용 후속 메시지는 대화의 최근 화면이 이 앱에서 올린 화면인지와 같은 작업이 실행 중인지 확인할 수 있을 때만 이동한다. 다중 모니터·DPI 환경과 캡처 제외 동작은 실제 환경에서 검증이 필요하다.

이동은 업로드 응답과 메시지 기록의 `image.state`가 모두 `ready`인 화면에만 허용한다. HTTP 응답을 잃어도 자기 기기의 `job started`나 재연결 시 작업 상태에서 작업 ID를 얻어 기록의 화면과 대조해 복구한다. `job ended`는 새 맥락 생성만 막고, 기존 작업의 마지막 이동은 `live done`까지 받는다. 이미 받은 이동은 차례로 끝까지 실행하며, 자동 말풍선 닫기와 복귀는 큐가 끝난 뒤 시작한다. 직접 드래그·이동 끄기 등 사용자의 중단은 즉시 적용한다. Windows 10 2004 이상에서는 캡처 제외를 먼저 적용하고, 실패하면 창을 잠깐 숨긴다.

화면 검증 중 작업이 끝나도, 검증 시작 시의 예약과 해당 요청의 화면 ID를 보존한다. 대화 상세의 작업 ID가 그대로이고 최신 첨부가 그 화면 ID이며 `ready`일 때만 수신해 둔 이동을 처리한다. 다른 작업·다른 화면·준비되지 않은 이미지에는 적용하지 않는다. `live done` 이후 새 이동을 받거나 종료한 작업을 새로 열지는 않는다.

화면을 첨부하지 않은 후속 메시지는 같은 대화에서 마지막으로 접수된 로컬 화면 ID를 검증 후보로 고정한다. 이 경우에도 서버의 최신 화면 ID·작업 ID·이미지 준비 상태를 대조하므로, 다른 PC가 새 화면을 보냈거나 화면이 만료되면 이동하지 않는다. 새 화면을 첨부한 요청은 항상 그 새 화면을 우선하며 이전 화면으로 대체하지 않는다.

글 메시지의 접수 여부가 불명확하면 기록의 `origin`(이 기기), 글, 전송 전 sequence를 확인한다(PR #129). 이전 서버가 `origin`을 제공하지 않으면 동일한 글만으로 접수를 확정하지 않는다. 이때 다시 보내기를 누르면 중복 가능성을 알리고 사용자가 선택한다. `not_a_screen`은 기록 전 거절로 처리하며 해당 화면은 재사용하지 않는다.

재연결 시 `activity.working[].job_id`를 우선 쓰고, 이전 서버에 작업 ID가 없으면 대화 상세의 `job.job_id`를 조회한다. 같은 서버·기기로 수동 재연결하면 화면 file id·좌표·재생 횟수와 미확정 전송 상태를 유지하고 새 연결에서 기록을 확인한다. 서버나 기기를 바꿀 때 미확정 전송이 남아 있으면 중복 가능성을 알리고 사용자가 전환을 선택한 경우에만 이전 상태를 정리한다. 이 복구 정보는 현재 앱 프로세스의 메모리에만 보관한다.

기기 전환 승인은 새 짝짓기 요청·대기 토큰 저장·활성 토큰 확정보다 먼저 받는다. 전환을 거부하면 기존 활성 자격 증명과 복구 정보를 유지한다. 이미 대기 중인 짝짓기를 복구할 때도 활성 자격 증명을 바꾸기 전에 승인을 확인한다.

구현한 범위: 짝짓기, 기기 토큰 저장, 대화 목록과 생성, 텍스트 전송·취소, 접속 신호, 사건 흐름과 자기 기기 작업의 실시간 응답·표정 수신. 네트워크 중단 시 입력은 유지하고 재접속한다. 활성 토큰과 대기 토큰을 별도로 보관하며 짝짓기 응답이 유실되면 재실행 시 등록 여부를 확인한다.

짝짓기에서 `token_in_use`가 발생하면 새 토큰으로 한 번 재시도한다. `pairing_busy`는 2초 간격으로 최대 두 번 재시도한다. 전송 중 Enter를 다시 눌러도 요청은 하나만 실행한다.

말풍선에는 대사와 `⋯`만 기본으로 표시한다. 캐릭터를 클릭하거나 단축키를 누르면 말풍선 아래에 입력란이 펼쳐지며, 연결 전에는 입력을 막고 연결 상태를 보여 준다. 대화 선택·새 대화·기록·멈춤·설정은 `⋯`에 있다. 답변 완료 후 읽을 시간을 두고 말풍선을 숨기며, 미전송 입력은 보존한다. 대화 기록 창은 일반 사용자 메시지와 답변의 `display.text`를 페이지별로 읽는다. 기본 표정에서는 눈 깜빡임과 입 움직임, 5분 이상 입력이 없을 때 눈을 감은 대기 동작을 시험할 수 있다.

현재 히마리의 내장 캐릭터 정의 `Himari.Companion/Assets/himari.json`은 말풍선 템플릿 `pixel`을 지정한다. 앱은 `pixel`과 `default`를 알고, 지정이 없거나 알 수 없는 템플릿은 `default`로 처리한다. 외부 캐릭터 패키지 설치·선택이나 별도 이미지 템플릿 불러오기는 아직 구현하지 않았다.

현재 제한: 생성 이미지의 프레임마다 세부가 달라 전환 시 흔들릴 수 있다. 표정별 말하기 프레임이나 파츠 애니메이션은 아직 없으며, 기기 API와 SSE를 실제 서버에서 함께 시험하거나 두 PC에서 확인하지 못했다.

가짜 HTTP 전송으로 요청 형식, SSE, 짝짓기 실패·응답 유실, 질문 응답 형태와 재연결 동기화 흐름을 확인하는 독립 테스트 (실제 Windows UI·서버 종단 간 테스트는 아님):

```powershell
dotnet run --project clients/windows/Himari.Companion.ContractTests/Himari.Companion.ContractTests.csproj
```
