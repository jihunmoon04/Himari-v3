# HIMARI Windows 앱

.NET 10 Windows Desktop SDK, Windows 10 1809 이상과 기기 API가 배포된 서버가 필요하다.

```powershell
dotnet run --project clients/windows/Himari.Companion/Himari.Companion.csproj
```

Web의 Devices에서 기기를 만들고 설정의 연결 탭에 HTTPS 주소와 짝짓기 코드를 입력한다. 토큰은 Windows 자격 증명 관리자에, 창 위치·크기·좌우반전·화면 첨부·표시 시간·단축키는 `%LOCALAPPDATA%\HIMARI\window.json`에 저장한다(토큰은 이 JSON에 저장하지 않음).

## 대화와 단축키

- 기본 단축키는 한 손으로 누를 수 있는 **Alt+Q**다. 다른 앱에서는 히마리 입력창으로, 히마리에서는 직전 작업 창으로 전환한다(최소화돼 있으면 복원). 입력창이 닫혀 있어도 전환 방향은 같다. Alt+Tab처럼 전환 자체는 작성 중인 말풍선을 숨기지 않는다. 캐릭터와 대화 창이 활성화된 동안 글자·한글·붙여넣기를 입력하면 입력창을 열어 이어 쓴다. 전환 직후 예약된 포커스 복구가 이전 앱의 포커스를 다시 가져오지 않도록 취소한다.
- 설정의 대화 화면 탭에서 Alt+Shift+Q, Ctrl+Space, 기존 Ctrl+Alt+H로 바꿀 수 있다. 다른 앱과 충돌하면 기존 등록을 복구하고 설정에 오류를 표시한다. 기본 키도 등록할 수 없으면 트레이나 캐릭터 클릭으로 대화를 연다.
- 이전 작업 창이 없거나 닫혔으면 데스크톱으로 포커스를 넘겨 히마리의 입력 포커스를 해제한다. 초안과 말풍선은 유지한다.
- 단축키는 별도의 메시지 전용 창에 등록해 대화 창의 표시·숨김과 관계없이 유지한다. 앱 표시가 끝난 뒤 등록도 다시 확인한다.
- Enter는 전송, Shift+Enter는 줄바꿈이다. PreviewKeyDown과 IME 조합 이벤트를 사용하며 조합·확정 Enter는 전송하지 않는다.
- 평소에는 두 말풍선이 모두 숨겨져 있다. 클릭·단축키로 작성하면 사용자 말풍선이, 답변이 들어오면 히마리 말풍선이 나타난다. 전송 후 사용자 말풍선에는 보낸 내용이 남는다.
- 전송은 사용자 말풍선 아래의 화살표, 답변 멈춤은 히마리 말풍선 하단의 사각형 아이콘이다. 긴 답변에서도 중지 버튼은 고정된다.
- 작성 중에는 이전 전송 글 대신 입력창만 표시하고, 전송이 확인되면 보낸 글을 표시한다. 응답을 기다리며 새로 작성한 글이 있으면 해당 초안과 입력창을 유지한다.
- 대화 선택·새 대화·기록·좌우반전·설정·말풍선 닫기·숨기기·종료는 캐릭터 우클릭 메뉴에 있다. 설정은 트레이에서도 연다.

## 화면·배치·도트 프레임

화면 첨부는 기본으로 켜져 있다. 설정의 대화 화면 탭에서 끌 수 있다. 보내는 순간의 화면이 서버와 모델로 전달되며 사용자 말풍선에 활성 여부를 작게 표시한다. 단축키로 대화에 들어왔으면 직전 작업 창의 모니터를 기억해 캡처한다. 캐릭터를 마우스로 클릭해 연 경우에는 기존 앞 창·포인터 규칙을 쓴다.

이름 표시는 생략하고 기본 입력창은 입력칸·화면 첨부 상태·전송 아이콘을 한 줄에 표시한다. 여러 줄을 입력할 때만 입력창이 자란다. 짧은 답변도 한 줄 높이에서 시작한다.

캐릭터와 말풍선은 별도 창이다. 캐릭터 창에는 말풍선을 위한 투명 여백을 두지 않으며, 채팅을 열거나 답변 길이가 바뀌어도 캐릭터 좌표를 보정하지 않는다. 말풍선만 현재 모니터 작업 영역 안에 배치하고 긴 내용은 내부에서 스크롤한다. 이전 설정의 큰 투명 창 좌표는 처음 한 번 캐릭터 위치로 옮겨 저장한다.

설정 → 대화 화면 → 말풍선 위치에서 **상 고정 / 하 고정 / 상하 자동**을 고른다. 기본 자동은 캐릭터 중심이 모니터 위쪽 절반이면 아래, 아래쪽 절반이면 위에 표시한다. 고정 방향에 공간이 모자라면 캐릭터를 옮기지 않고 말풍선만 화면 안으로 보정하므로 일부 겹칠 수 있다. 두 말풍선은 같은 너비와 중앙선을 사용하고 새 말풍선은 캐릭터에 가까운 쪽에 놓인다. 아래 배치에서는 쌓이는 순서와 꼬리 방향을 함께 반전하되 글자는 정상 방향이다. 사용자는 크림색, 히마리는 연보라색이다. 스트리밍 중인 같은 답변·재연결·늦은 전송 확인은 순서를 다시 바꾸지 않는다. Grid 행만 바꾸므로 초안·선택 영역·IME 조합을 유지한다. 좌우반전은 이미지·대화 열·꼬리와 화면을 가리키는 기준점을 함께 바꾼다.

도트 프레임은 `PixelBubble`이 4 DIP 격자의 계단형 모서리·테두리·꼬리를 직접 그리는 WPF 그래픽이다. 문장이 길어져도 모서리를 늘이지 않으며, 본문 한글은 가독성을 위해 일반 텍스트로 그린다. 캐릭터 이미지는 기존 생성 시안을 사용한다. 프레임 간 세부 차이로 전환 시 흔들릴 수 있고 파츠 애니메이션·외부 테마 설치는 아직 없다.

각 말풍선의 유지 시간은 별도로 계산하되 자동 숨김은 배치 방향과 관계없이 오래된 말풍선부터 진행한다. 유지 시간은 설정의 최소 시간 + Unicode 글자 수 × 100자당 추가 시간이며 최대 5분이다. 새 말풍선의 시간이 먼저 끝나면 오래된 말풍선이 사라질 때까지 기다리고, 오래된 말풍선을 숨긴 다음에도 최소 2초 뒤에 숨긴다. 입력·마우스 확인·전송 중·결과 불명 메시지는 자동으로 숨기지 않는다. 오래된 말풍선이 이런 보호 상태이면 새 말풍선도 건너뛰어 숨기지 않는다. 답변·이동 큐가 끝난 뒤 히마리의 읽기 타이머가 시작되며 답을 기다리는 질문도 자동으로 숨기지 않는다. 직접 말풍선을 닫아도 미전송 입력은 보존한다.

이 앱에서 접수된 메시지의 작업 ID와 전송 전 기록 순서를 기억한다. 연결이 끊긴 동안 답변이 완료되면 같은 서버·기기·작업의 새 최종 답변을 처음 확인했을 때 말풍선을 열고, 이동 큐가 끝난 뒤 읽기 타이머를 시작한다. 작업 종료와 Live 완료가 HTTP 202보다 먼저 도착해도, 접수 응답 뒤 완료 상태를 다시 확인해 아직 보지 못한 최종 답변을 복구한다. 정상 Live로 표시를 마친 답변이나 이미 복구한 답변은 재조회로 다시 열지 않는다. 기록 탐색만으로 과거 답변을 자동 표시하지 않는다. 이 대기 정보는 재연결 동안 메모리에 유지되며 앱 재시작 시에는 복구하지 않는다.

대화가 숨겨진 상태에서도 연결 실패 시 캐릭터 옆에 작은 `!` 표시가 나온다. 마우스를 올리면 상태를 읽을 수 있고 클릭하면 설정을 연다. 연결이 복구되면 표시가 사라진다.

## 마크다운과 전체화면

말풍선은 제목·강조·목록·인용·링크·인라인 코드와 짧은 코드 블록을 WPF 서식으로 표시한다. 본문은 선택·복사할 수 있다. 표·수식은 확장 보기 안내를 표시하고, 긴 코드 블록은 앞부분만 보여 준다. 답변 모서리의 작은 확장 아이콘은 같은 도트 말풍선을 넓혀 표·수식·가로 스크롤 코드를 표시한다. 다시 누르면 원래 크기로 접는다. 별도 창을 만들지 않으며 스트리밍도 따라간다. 투명 말풍선 안의 렌더링에는 WebView2CompositionControl을 사용한다. 기존 웹의 안전한 렌더러와 KaTeX를 앱에 포함하므로 답변을 외부 서버로 보내지 않는다. 확장 보기에는 Microsoft Edge WebView2 Runtime이 필요하며 사용할 수 없으면 기본 서식을 제공한다.

Alt+Q와 일반 Alt+Tab 진입을 모두 관찰한다. 직전 작업 창이 살아 있는 전체화면 창이면 히마리가 활성화된 동안 Shell의 `MarkFullscreenWindow`로 전체화면 작업 표시줄 순서를 유지한다. 다른 앱·설정으로 전환하거나 영상의 전체화면이 끝나거나 창이 닫히면 해제한다. Explorer 창을 숨기거나 시스템 작업 표시줄 설정을 바꾸지 않는다. 크롬 유튜브의 실제 재생 전환은 별도 실기 확인이 필요하다.

## 서버 계약과 복구

화면 전송과 이동은 서버 PR #126의 계약을 기준으로 구현했다. 글 전용 후속 메시지는 대화의 최근 화면이 이 앱에서 올린 화면인지와 같은 작업이 실행 중인지 확인할 수 있을 때만 이동한다. 다중 모니터·DPI 환경과 캡처 제외 동작은 실제 환경에서 검증이 필요하다.

이동은 업로드 응답과 메시지 기록의 `image.state`가 모두 `ready`인 화면에만 허용한다. HTTP 응답을 잃어도 자기 기기의 `job started`나 재연결 시 작업 상태에서 작업 ID를 얻어 기록의 화면과 대조해 복구한다. `job ended`는 새 맥락 생성만 막고, 기존 작업의 마지막 이동은 `live done`까지 받는다. 이미 받은 이동은 차례로 끝까지 실행하며, 자동 말풍선 닫기와 복귀는 큐가 끝난 뒤 시작한다. 직접 드래그·이동 끄기 등 사용자의 중단은 즉시 적용한다. Windows 10 2004 이상에서는 캡처 제외를 먼저 적용하고, 실패하면 창을 잠깐 숨긴다.

화면 검증 중 작업이 끝나도, 검증 시작 시의 예약과 해당 요청의 화면 ID를 보존한다. 대화 상세의 작업 ID가 그대로이고 최신 첨부가 그 화면 ID이며 `ready`일 때만 수신해 둔 이동을 처리한다. 다른 작업·다른 화면·준비되지 않은 이미지에는 적용하지 않는다. `live done` 이후 새 이동을 받거나 종료한 작업을 새로 열지는 않는다.

화면을 첨부하지 않은 후속 메시지는 같은 대화에서 마지막으로 접수된 로컬 화면 ID를 검증 후보로 고정한다. 이 경우에도 서버의 최신 화면 ID·작업 ID·이미지 준비 상태를 대조하므로, 다른 PC가 새 화면을 보냈거나 화면이 만료되면 이동하지 않는다. 새 화면을 첨부한 요청은 항상 그 새 화면을 우선하며 이전 화면으로 대체하지 않는다.

글 메시지의 접수 여부가 불명확하면 기록의 `origin`(이 기기), 글, 전송 전 sequence를 확인한다(PR #129). 이전 서버가 `origin`을 제공하지 않으면 동일한 글만으로 접수를 확정하지 않는다. 이때 다시 보내기를 누르면 중복 가능성을 알리고 사용자가 선택한다. `not_a_screen`은 기록 전 거절로 처리하며 해당 화면은 재사용하지 않는다.

재연결 시 `activity.working[].job_id`를 우선 쓰고, 이전 서버에 작업 ID가 없으면 대화 상세의 `job.job_id`를 조회한다. 같은 서버·기기로 수동 재연결하면 화면 file id·좌표·재생 횟수와 미확정 전송 상태를 유지하고 새 연결에서 기록을 확인한다. 서버나 기기를 바꿀 때 미확정 전송이 남아 있으면 중복 가능성을 알리고 사용자가 전환을 선택한 경우에만 이전 상태를 정리한다. 이 복구 정보는 현재 앱 프로세스의 메모리에만 보관한다.

기기 전환 승인은 새 짝짓기 요청·대기 토큰 저장·활성 토큰 확정보다 먼저 받는다. 전환을 거부하면 기존 활성 자격 증명과 복구 정보를 유지한다. 이미 대기 중인 짝짓기를 복구할 때도 활성 자격 증명을 바꾸기 전에 승인을 확인한다.

계약 테스트는 가짜 HTTP로 전송·이동·설정 마이그레이션·단축키 등록 복구·이전 창 선택 정책을 검증한다. UI 테스트는 실제 라우팅 이벤트와 앱 컨트롤로 Enter·합성 IME 조합, 기본 숨김·양방향 배치·긴 답변 중지 버튼, 말풍선 색·표시 순서·오래된 말풍선부터 숨김·늦은 접수 응답·재연결 시 새 초안의 순서 보존을 검증한다. 오프라인으로 띄운 분리 창에서는 화면 네 모서리의 캐릭터 좌표 보존, 위·아래 배치와 역방향 만료 순서, 첫 글자 보존, 전환 후 포커스 해제, 선택 영역·IME 조합 유지를 검증한다. WebView2 Runtime이 설치돼 있으면 실제 확장 보기에서 표·KaTeX·긴 코드와 외부 이미지/스크립트 차단도 검증한다(테스트용 임시 프로필 사용).

`--screenshots`는 연결·자격 증명·설정 저장·화면 캡처 없이 실제 WPF 컨트롤을 PNG로 렌더링한다. `--native-presentation`은 Shell 전체화면 표시·해제 호출과 별도 프로세스 전체화면 창을 검사한다. Windows가 백그라운드 테스트의 전경 창 전환을 거부하면 전환 검사는 건너뛰었다고 출력한다. 크롬 유튜브 실제 재생과 Alt+Tab/Alt+Q 왕복, OS 단축키 충돌, 실제 한국어 IME 키보드 조작과 다중 모니터 DPI 전환은 실기 확인이 필요하다.
